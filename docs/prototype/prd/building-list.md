## 0. 화면 구조 (통합 master-detail)

- 한 화면에서 **위 = 건물 목록(마스터)**, **아래 = 선택 건물의 입주민(디테일)** 을 동시에 다룬다.
- 건물 행을 선택하면 그 행이 **청록 틴트**로 강조되고, 하단 입주민 표가 해당 건물로 채워진다.
- 입주민(디테일) 영역의 규칙은 `tenant-list.md` 참조.
- **테마: 청록(#14A497) 계열** — 프로토타입 Figma 준수(2026-08-28 결정). 앱 메인 파랑 기조와 별개로 이 화면은 청록.

## 3. UI

### 3.0 상단 앱바

- **기능**: 화면 제목 + 출력 진입
- **규칙**:
  - 좌측 제목: `건물·입주자 관리`
  - 우측 `입주자카드 및 부과내역 출력` 버튼 → 선택된 건물의 입주자카드/부과내역 출력(`/api/buildings/:id/tenant-cards`). 건물 미선택 시 "건물을 먼저 선택해 주세요" 안내.
  - 부과내역서는 관리비 부과 확정(P5) 이후 활성.

### 3.1 검색 바

- **기능**: 건물명·주소로 목록 검색
- **규칙**:
  - 필터 버튼 + `건물명·주소 검색` 입력 + `검색` 버튼(청록)
  - `검색` 버튼 클릭 또는 Enter 시 목록을 재조회한다(실시간 필터 아님).
  - 담당자 유형(관리/검침/청소) 필터는 필터 버튼 뒤 패널로 제공 예정(후속 배선).

### 3.2 건물 목록(마스터) 카드

- **기능**: 등록된 건물을 행 단위로 표시하고, 행을 선택해 하단 입주민을 로딩
- **규칙**:
  - 헤더: `전체 건물` + 건수 배지(`N곳`) + `⤓ 엑셀 다운` + `＋ 건물 등록`
  - 표시 컬럼(12): **코드 / 건물명 / 유형 / 주소 / 건물주명 / 건물주 연락처 / 공동현관 / 관리 / 검침 / 청소 / 등록일 / 동작**
    - `유형·건물주명·건물주 연락처·공동현관·등록일` 은 `list_buildings` RPC 확장 전까지 빈 셀로 노출(가용 데이터 우선 결정, 후속 배선).
  - 행 **클릭** → 해당 건물 선택(청록 틴트) + 하단 입주민 표 로딩
  - 행의 `동작 > 상세` → `/buildings/:id` (건물 상세·등록 화면)
  - `＋ 건물 등록` → `/buildings/new`
  - `⤓ 엑셀 다운` → 현재 검색 조건이 적용된 목록을 `.xlsx` 로 다운로드
    - 다운로드 파일명: `건물목록_YYYYMMDD.xlsx`
  - 기본 정렬: 등록일 최신순
  - 페이지네이션: 페이지 번호 방식, 페이지당 노출 건수 드롭다운(10 / 20 / 50건, 기본 20)
  - 마스터를 컴팩트하게 유지하기 위해 목록 영역은 고정 높이 내에서 세로 스크롤(헤더 고정)

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 빈 상태 (empty) | 등록된 건물이 0개 | "등록된 건물이 없습니다" 안내 + `건물 등록` 버튼 노출 |
| 로딩 | 목록 조회 중 | 테이블 영역 로딩 인디케이터 표시 |
| 성공 | 건물 1개 이상 존재 | 목록 정상 표시 |
| 결과 없음 | 필터 조건에 맞는 건물 0건 | "조건에 맞는 건물이 없습니다" 안내 |
| 에러 | 목록 조회 실패 | "데이터를 불러오지 못했습니다. 다시 시도해 주세요." |
