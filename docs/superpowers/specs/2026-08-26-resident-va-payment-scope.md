# 결제 연동 스코프 결정 — 입주자 관리비 온라인 수납 (PG 고정 가상계좌)

- **일자**: 2026-08-26
- **상태**: **방향 확정**(우선순위·접근). 구현 계획(writing-plans)은 실제 착수 시점에 별도 수립.
- **관련 문서**: PRD `docs/prototype/prd/tenant-app.md`, `docs/prototype/prd/payment-processing.md` · 검증 리포트 `docs/audit/rls-verification-2026-08-26.md`

---

## 1. 배경 / 현재 상태

- 현 관리비 수납 모델(PRD 2026-07 기준):
  - **입주자앱**(`tenant-app.md`): 관리비 확인은 **읽기 전용** + **입금계좌·금액 복사** → 입주자가 본인 은행앱에서 **수동 이체**. 자동이체 세대는 "자동이체 세대입니다" 안내만.
  - **직원 수납**(`payment-processing.md`): 수동수납 / 지로 / **은행엑셀 자동매칭(고객번호→이름→금액)** / 효성CMS(엑셀 다운·붙여넣기, **API 직접연동 제외**).
- 코드에 PG/결제대행 통합 흔적 **0** (그린필드).
- **핵심 페인**: 은행 입금내역을 엑셀로 **수기 대사**하고 미매칭 건을 수동 처리.

## 2. 결정

**입주자 관리비 온라인 수납을 PG 기반 "세대별 영구 고정 가상계좌(VA)"로 도입한다.**

- 입금 → PG **webhook** → VA로 세대 식별 → 해당 기간 부과에 **자동 수납 반영**(기존 `payments`·미납/연체료 로직 재사용).
- **관리업체(org)별** PG 머천트/정산계좌. 설정·데이터는 org 스코프(RLS 준수).
- 입주자 UX: 기존 "계좌 복사"를 **"가상계좌 복사"(+금액 함께 복사)** 로 대체 — 전환 저항 최소.

**근거**: 현 페인(수기 대사)을 직접 해결, 기존 UX와 연속, 통합 최단, 정기 관리비 성격에 최적.

## 3. 대안 비교 (요약)

**레일**
- **가상계좌 ✅ (채택)** — 수기 대사 직접 해결 + UX 연속성 + 통합 최단.
- 간편결제(카카오/네이버/토스) — 카드수수료 ~2-3%, 관리비 저마진에 부담.
- 오픈뱅킹 — 이용기관 등록·보증·심사 장벽, 출금동의 마찰.
- CMS 자동이체(API) — 가입·출금동의·심사, 신규 등록 전환 부담.

**VA 형태**
- **PG 고정(세대 영구) ✅ (채택)** — 매월 같은 계좌, 정기 관리비 최적, UX 연속.
- PG 건별(고지서별·만료) — 매월 새 계좌 통지 부담, 발급비↑, 습관 깨짐.
- 은행 직접 펌뱅킹 — 수수료 최저·직입금이나 은행별 계약·통합 무겁고 리드타임 김(1차 과함).

## 4. 스코프

**In**
- org별 PG 가상계좌 발급·세대 매핑·설정
- 입금 webhook 수신 → 자동 대사 → `payments` 반영 (멱등)
- 세입자앱/무로그인 상세의 VA 표시·복사 UX
- 대사/정산 조회

**Out (당분간)**
- 간편결제·오픈뱅킹·CMS-API·카드결제 (본 결정 제외, 추후 재검토)
- 은행 직접 펌뱅킹

## 5. 기존 시스템 연계

- `payments` 테이블·수납상태·미납/연체료 로직 **재사용**. VA 자동수납이 수동/엑셀 매칭을 **대체·보완**.
- 은행엑셀 매칭·지로·효성CMS와 **당분간 병행** → VA 수납 비중 증가에 따라 점진 이관.
- **RLS/보안**(검증된 패턴 준수): VA/매핑/설정 테이블은 `org_id` 스코프. webhook 처리 라우트는 service_role 사용하되 **서명 검증 + org 서버 도출 + 멱등**(A 감사에서 확인한 라우트 패턴과 동일).

## 6. 단계

- **P1** PG 벤더 선정·org별 계약 · VA 스키마 · 세대↔VA 배정
- **P2** webhook 수신 → 자동대사(→`payments`) · 부분/초과입금·연체료 매칭 규칙 · 실패/재시도(멱등)
- **P3** 세입자앱/무로그인 상세 VA UX · 알림톡 안내
- **P4** 정산·대사 대시보드 · 기존 수단 병행→이관

## 7. 구현 착수 시 결정할 오픈 항목 (오늘 미결정, 명시적 보류)

1. **PG 벤더**: PortOne(멀티PG 어그리게이터) vs 토스페이먼츠/나이스페이 직계약 — 기존 계약 유무 확인
2. **수수료 부담 주체**: 건물/관리업체 vs 입주자 전가 (관리비 전가 제약 검토 필요)
3. 세대 영구 VA의 **이사(입주자 교체) 시 승계/재발급** 정책
4. **부분납·초과납·연체료 매칭 규칙** (기존 원금/분할 로직과 정합)
5. **이사정산**(`moving_settlements`)·환급과의 상호작용
6. PG 정산계좌 → 건물/관리업체 **지급 주기·수수료 차감·회계 반영**
7. **보안**: webhook 서명 검증·재전송 멱등·입금액 위변조 방지

## 8. 비목표 (YAGNI)
