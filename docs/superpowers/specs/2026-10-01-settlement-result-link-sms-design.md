# 정산 결과 비회원 링크 문자 — 설계

- 작성: 2026-10-01
- 상태: 1·2부 사용자 승인, 3부 제안(리뷰 때 확정), 구현 전
- 관련: 마이그 0216(퇴실 신청 세대 기준)·0217(퇴실 시 세입자 앱 연결 해제), 고지서 서명 링크 0146

## 배경

- 기획 결정(2026-10-01): 퇴실하면 세입자 앱 연결을 끊는다(0217 적용 완료). 정산 결과는 앱 화면이 아니라 **문자 템플릿**으로 안내한다.
- 사용자 결정: 문자에 **로그인 없이 여는 정산 결과 링크**를 넣는다. 금액은 손으로 입력하지 않는다. 직원은 지금 쓰는 문자 보내기 창에서 세대를 골라 템플릿으로 보낸다.
- 지금 있는 것
  - 문자 보내기 창(`components/messenger/MessengerFab.tsx`): 입주자 → 건물 → 호실 선택. 입주자 목록은 입주·이사 중 세대만이고 공실은 빠진다(`list_tenants`).
  - 자동으로 채워지는 변수는 이름·호실·건물명뿐이다(`lib/messaging/preset.ts` `buildRecipientRenderVariables`). 그 밖의 변수는 화면 프리셋이 채우지 않으면 발송이 막힌다.
  - 고지서 비회원 링크는 미납관리 화면 프리셋만 수신자별로 만들어 넣는다(`OverdueWorkspace.tsx:220`, `staff_sign_bill_urls`).
  - 정산 비회원 페이지 `/share/settlement/[token]`(0101 토큰, 완료된 정산만, 만료 30일 0175)은 있으나 직원 화면에 발급 버튼이 없다.
  - `moving_settlements`: `unit_id`(필수)·`occupancy_id`·`status`(draft·saved·mid_moveout·completed)·`move_out_date`·`settlement_amount`·`created_at`·`updated_at`. 완료 시각 칸은 없다.

## 결정 사항

1. **보내는 곳**: 기존 문자 보내기 창. 새 진입점은 만들지 않는다.
2. **보내는 시점**: 이사정산 입력을 저장한 뒤, [정산완료+퇴실]을 누르기 전. 정산완료+퇴실 뒤에는 공실이라 문자 창 목록에서 빠진다.
3. **링크**: 그 세대의 **진행 중 정산 건**에 묶인 **서명 링크**(고지서 0146 방식). DB에 따로 쓰는 것 없이 바로 만든다.
4. **정산 건이 없는 세대**: 발송을 막고 알린다.
5. **채널**: 문자(SMS)만. 알림톡은 카카오 템플릿 승인이 필요해 범위 밖.
6. **비회원 페이지 상태**: 진행 중 / 완료 / 만료 / 잘못된 링크.
7. **유효기간**: 정산 완료 후 30일. 완료 전에는 만료되지 않는다(공개 링크 30일 정책과 같음).

## 1부 — 링크와 정산 건 연결 (승인)

- 템플릿 변수 `#{정산링크}`를 새로 둔다.
- 링크를 만드는 서버 함수(가칭 `staff_sign_settlement_links(p_unit_ids bigint[])`)
  - 같은 관리업체이고 문자 발송 권한(`messaging` 모듈)이 있는 직원만 호출할 수 있다.
  - 세대마다 **지금 입주 기간의 진행 중 정산 건**을 고른다: `status in ('draft','saved')`이면서 그 세대 마지막 퇴실(`occupancy_history.created_at` 최댓값) 이후에 만든 건 중 최신. 0217 방어선과 같은 기준이라 예전 입주자의 정산은 잡히지 않는다.
  - 반환: 세대·건물·정산 건 번호·서명. 진행 중 정산 건이 없으면 그 세대는 결과에 없다.
- 서명: 고지서 `bill_signature`(0146)와 같은 비밀값(`app_secrets`)으로 HMAC-SHA256 base64url을 만들되, 메시지에 정산 전용 접두어를 붙여 고지서 서명과 섞이지 않게 한다. definer 전용이고 anon·authenticated에는 열지 않는다. pgcrypto는 `extensions.hmac`으로 스키마를 붙여 부른다(0146 함정).

## 2부 — 비회원 페이지와 유효기간 (승인)

- 주소: `/share/settlement/signed/[건물]/[세대]/[정산건]?s=서명`. 기존 토큰 주소 `/share/settlement/[token]`은 그대로 둔다(같은 자리에 다른 이름의 동적 경로를 둘 수 없어 `signed` 고정 경로를 둔다).
- 공개 조회 함수(가칭 `public_settlement_by_signed`, anon): 서명이 맞고 정산 건이 그 건물·세대 것일 때만 1행을 돌려준다. 틀리거나 지워졌거나 다른 세대 것이면 0행.
- 화면(기존 `PublicTokenPageShell`·`PublicShareArticleCard`·`ResidentAsyncState` 재사용)
  - **진행 중**(draft·saved): 건물·호실과 "정산을 진행하고 있어요. 정산이 끝나면 이 링크에서 결과를 볼 수 있어요." 금액은 보여 주지 않는다.
  - **완료**(completed·mid_moveout): 지금 토큰 페이지처럼 퇴실일·정산구분·정산금액. 계산은 `public_settlement_by_token`(0175)과 같게 한다.
  - **만료**: "만료된 링크예요. 관리사무소에 새 링크를 요청해 주세요."(기존 문구)
  - **잘못된 링크**: "유효하지 않은 링크예요."(기존 문구)
- 유효기간: `moving_settlements.completed_at`을 새로 둔다. 상태가 처음 completed·mid_moveout으로 바뀔 때 트리거가 `now()`를 기록하고, 기존 완료 건은 `updated_at`으로 채운다. 만료 = `completed_at + 30일`, 완료 전에는 만료 없음.
- 개인정보: 세입자 이름·전화는 보여 주지 않는다(기존과 같음).

## 3부 — 문자 창·템플릿 동작 (제안, 리뷰 때 확정)

- 템플릿 관리 탭(`TemplateFormModal`) 변수 넣기 버튼에 `#{정산링크}`를 추가한다. `AUTO_VARS`에도 넣어 수동 입력 칸으로 취급하지 않는다.
- 문자 보내기 창: 본문에 `#{정산링크}`가 있고 채널이 문자일 때, 선택한 입주자 수신자들의 세대로 링크 함수를 한 번에 부른다(React Query). 받은 링크를 수신자별 변수 `정산링크`로 채운다.
- 링크가 없는 세대가 있으면 "정산 내용을 먼저 저장해 주세요: 그린빌라 999호…"처럼 알리고, 그 세대를 빼기 전까지 [보내기]를 막는다.
- 입주자가 아닌 수신자(건물주·직원 등)에게 이 변수를 쓰면 기존 규칙대로 미해결 변수로 막힌다.
- 미리보기에는 첫 수신자의 실제 링크를 보여 준다.

## 범위 밖

- 알림톡(시드 기본 템플릿 0098의 정산 안내 `#{상세링크}` 버튼 포함), 이사정산 화면의 발송 버튼, 문자 창의 '퇴실(정산 완료) 세대' 수신 대상.
- 이사정산 수납액·미수금 미저장(알려진 결함), 정산 결과 기본 문자 템플릿 시드(필요하면 리뷰 때 결정).
- PRD 반영은 기획자 몫이다(이 MCP로 고치면 버전 이력이 기획 담당 계정으로 남는다).

## 검증

- `tsc --noEmit`·바뀐 파일 eslint.
- 운영 DB 롤백 시험: 정상 서명 → 진행 중 / 완료 전환 → 결과 / 완료 31일 뒤 → 만료 / 위조 서명·다른 세대·지운 정산 건 → 0행 / 예전 입주 기간 정산 건은 링크 함수에서 안 잡힘 / 권한 없는 직원 거부.
- :3000에서 문자 창 미리보기·차단 안내, 비회원 페이지 4상태 확인. 단위 테스트는 쓰지 않는다(프런트 테스트 E2E 정책).
