# wbs-commit-sync 설계 스펙

- 작성일: 2026-08-10
- 상태: 승인됨(구현 계획 대기)
- 대상 저장소: `home_erp` (branch: angelshark)

## 1. 배경

WBS는 외부 앱 `https://master.d3dm23jgw6q2xw.amplifyapp.com/wbs` 에서 관리하며,
그 백엔드는 원격 MCP(Supabase Edge Function, 세션에는 `mcp__claude_ai__*` 도구로 연결)로 노출된다.

`auraworks/my-marketplace` 마켓플레이스에 **`wbs-scheduler` 플러그인(작성자 LaLa)** 이 이미 존재하며,
WBS를 **읽고 쓰는 도구층**(일정·화면상태·담당자·페이지 CRUD, 대화형)을 제공한다.
따라서 "쓰기 계층"은 재구축하지 않고 그대로 재사용한다.

**아직 없는 것** = 이 스펙이 만들 것:
- git 커밋을 읽어오는 부분
- 커밋 ↔ 화면(page) **유사도 매칭**
- **자동 트리거**(커밋 시 / 요청 시 일괄 / 주기적)
- 워터마크·학습맵(중복 처리·재매칭 방지)

## 2. 목표 / 비목표

**목표**: 내가(Claude) 만든 git 커밋을 읽어, 유사도로 주택관리ERP 버킷의 화면(page)에 매칭하고,
해당 화면의 **개발 트랙 상태/비고**를 WBS에 자동 반영한다.

**비목표**:
- 기획/디자인·퍼블리싱 트랙은 건드리지 않는다(개발 트랙만).
- 화면 생성/삭제/제목변경, 담당자 배정, 프로젝트 일정 설정은 다루지 않는다(그건 `wbs-scheduler`의 몫).
- `완료` 상태 자동 판정은 하지 않는다(사람이 명시할 때만).
- 주택관리ERP 외 다른 버킷은 절대 다루지 않는다.

## 3. 데이터 모델 (재확인)

- **bucket** = 프로젝트. 대상 버킷: **주택관리ERP** `9514ec1f-cb2d-4cfa-9ee6-6aff04127c73`
- **page** = 화면. 화면마다 3개 트랙(기획/디자인·퍼블리싱·개발) × `상태/목표일/완료일` + `remarks`(자유텍스트)
- 개발 트랙 필드: `dev_status`(예정|진행중|완료) · `dev_target` · `dev_done` · `remarks`

재사용 MCP 도구: `list_buckets`, `list_pages`, `get_project_status`, `get_page`,
`update_page_wbs`, `update_pages_wbs`.
(쓰기는 `update_page_wbs` / `update_pages_wbs`만 사용한다.)

## 5. 엔진 흐름

### 5.1 동기화(sync) — 요청/커밋/주기 공용

1. **가드**: `config.json` 로드 → `list_buckets`로 `bucket_id`가 여전히 이름 `주택관리ERP`에
   매핑되는지 확인. 불일치면 **중단**(타 버킷 오염 방지).
2. **커밋 수집**: `state.json`의 워터마크 이후 커밋을 `git log <last_sha>..HEAD`(설정 브랜치)로 수집.
   각 커밋에서 신호 추출:
   - 제목/본문 텍스트 (예: `feat(p1a): vendor-management 거래처/구분 삭제 UI`)
   - 변경 파일 경로 (`git show --name-only`)
   - 참고: 커밋 scope `(p1a)`는 **단계**이지 화면이 아니다. 화면 신호는 설명문의
     영문 kebab 토큰(vendor-management 등)과 한국어 명사(거래처/구분/건물/입주자/계정/권한 등).
3. **매칭**(커밋별): 신뢰도는 별도 임베딩/점수 계산 없이 내가 판단하는 **정성 밴드**(고신뢰/애매)다.
   - (a) `map.json` 키워드/경로 규칙 조회 → 히트 시 결정적 매칭 = **고신뢰**.
   - (b) 미스 시 `get_project_status`(또는 `list_pages`)로 화면 목록을 받아 커밋 신호와 대조.
   - (c) **명백한 단일 후보**(제목/키워드가 뚜렷이 일치) → 고신뢰 = **수용 + `map.json`에 규칙 학습**.
   - (d) 후보가 복수이거나 뚜렷한 일치가 없음 → **질문 대기 목록**에 넣음.
4. **쓰기**(고신뢰만, 버킷 잠금 준수):
   - 대상 화면의 현재 상태를 `get_project_status`로, `remarks`를 `get_page`로 **먼저 읽는다**(멱등).
   - `dev_status`: 현재 `예정`이면 `진행중`으로. 이미 `진행중`/`완료`면 **건드리지 않음**
     (다운그레이드 금지, 완료 자동 금지).
   - `remarks`: §8.2 규칙으로 자동 블록만 갱신(사람 작성분 보존).
   - 여러 화면에 **동일 값**을 넣는 경우 `update_pages_wbs`로 일괄, 아니면 `update_page_wbs`.
5. **질문**: 질문 대기 목록의 각 커밋에 대해 후보 화면(상위 N개)을 제시하고 사용자 선택을 받음
   → 선택 결과를 `map.json`에 학습 → 반영.
6. **워터마크 갱신**: `state.json.last_synced_sha = HEAD`, 처리 SHA 기록.
7. **리포트**: 표로 요약 — `커밋 → 화면 · 변경 필드 · 신뢰도/스킵/애매`.

### 5.2 백필(backfill) — 최초 1회, 미리보기 모드

- 5.1의 1~3을 **전체 이력**(설정 브랜치의 처음~HEAD)에 적용.
- 단, 4번(쓰기)을 하지 않고 **미리보기 표만** 출력(커밋 그룹 → 화면 → 제안 상태/remarks).
- 사용자가 OK → 실제 반영 → 워터마크를 HEAD로 세팅.
- 애매 항목은 미리보기 단계에서 함께 질문·확정하여 시드 맵을 채운다.

## 6. 트리거 (엔진 공용, 3종 모두)

- **요청 시 일괄**: 사용자가 "WBS 동기화" 또는 `/wbs-commit-sync` → 5.1 실행.
- **내 커밋 시**: `CLAUDE.md`(= `@AGENTS.md` 아래)에 규칙 1줄 추가 —
  "커밋 직후, 그 커밋이 건드린 화면을 wbs-commit-sync로 동기화한다." → 내가 세션에서 준수.
- **주기적**: 활성 세션에서 `/loop`로 5.1 반복 실행.
  - ⚠️ 클라우드 헤드리스 cron은 이 MCP가 미연결일 수 있음 → **세션 내 loop 또는 요청 시**를 1차로 권장.

### 7.3 .wbs/state.json (gitignore)
```json
{
  "last_synced_sha": "d36080c",
  "processed_shas": ["d36080c", "4eca126"],
  "updated_at": "2026-08-10"
}
```
- `processed_shas`는 리베이스/체리픽 등 비선형 이력에서의 중복 방지용. 과도히 커지면 최근 N개로 정리.

## 8. 안전장치

### 8.1 요약
- **버킷 잠금**: `bucket_id` 고정 + 쓰기 전 이름 재검증. 타 버킷(PickleKR·자수 등) 절대 금지.
- **개발 트랙만**: `dev_*`와 `remarks`만 쓴다. design/pub 필드는 절대 안 건드림.
- **완료 자동 금지**: `dev_status`를 `완료`로 자동 전환하지 않는다(사람이 명시할 때만).
- **다운그레이드 금지**: `진행중`/`완료`를 낮추지 않는다.
- **멱등**: 워터마크 + 읽고-쓰기. 재실행해도 같은 결과.
- **애매하면 질문**: 임계값 미만/후보 복수는 추측하지 않고 물어본다.

### 8.2 remarks 자동 블록 규칙
- remarks의 **자동 영역은 항상 꼬리에** 두고, 아래 헤더 라인으로 구분한다:
  ```
  —— [자동 동기화] ——
  착수 2026-08-07 · 최근 2026-08-10 · 커밋 5 · 최신: 계정·권한 삭제 UI
  ```
- 갱신 시: 기존 remarks에서 `—— [자동 동기화] ——` 라인부터 끝까지를 잘라내고 새 블록으로 교체.
  그 라인 **위의 사람 작성 텍스트는 그대로 보존**한다. 헤더가 없으면 사람 텍스트 뒤에 새로 붙인다.

## 10. 엣지 케이스

- **매칭 화면 없음**: 인프라/설정/문서 커밋(예: `chore`, 순수 `docs`)은 화면과 무관 → 스킵하고 리포트에 명시.
- **한 커밋이 여러 화면**: 각 화면에 개별 반영(신뢰도 각각 판단).
- **여러 커밋이 한 화면**: remarks 자동 블록의 커밋 수·최신 요약만 누적, 상태는 멱등.
- **리베이스로 SHA 변경**: `processed_shas`로 중복 회피, 최악의 경우 remarks가 멱등이라 안전.
- **버킷 이름 변경**: 가드에서 불일치 → 중단하고 사용자에게 알림.

## 11. 검증 방법

- **드라이런/백필 미리보기**: 실제 쓰기 전 매핑 표로 육안 확인.
- **멱등성 테스트**: 같은 동기화를 두 번 실행 → 두 번째는 변경 0건이어야 함.
- **버킷 잠금 테스트**: `config.bucket_id`를 잘못된 값으로 두면 가드에서 중단되는지 확인.
- **remarks 보존 테스트**: 사람이 쓴 remarks가 있는 화면에 동기화 → 사람 텍스트 유지 + 자동 블록만 갱신.

## 12. 미해결 사항

- 없음(설계 결정 완료). 구현 중 `get_page`가 `remarks`를 반환하는지 실호출로 최종 확인.
