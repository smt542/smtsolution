# 알림톡 템플릿 문안 사전 작성 (카카오 심사 제출용)

> **목적**: 카카오 알림톡 채널→Popbill 연동·**템플릿 승인은 며칠 소요**되는 크리티컬 패스다. 채널이 열리는 즉시 제출할 수 있게, 발송 케이스별 **문안·변수·버튼·유형**을 규격에 맞춰 미리 확정한다.
> **상태**: draft · 2026-08-25 · 승인 대기(사용자 리뷰)
> **근거**: `docs/prototype/prd/messaging.md`(§3 컨텍스트 진입·§4.2 템플릿), `lib/messaging/render.ts`(변수 `#{키}` 규격), 세입자 무로그인 상세 라우트 `app/(resident)/r/[token]/page.tsx`.

---

## 0. 공통 규격 (카카오 알림톡 심사 기준)

- **정보성 메시지 전용** — 수신자와의 거래·이용 관계에 기반한 안내만. 광고·홍보 문구 0. (7종 전부 해당)
- **변수 형식** `#{키}` — 시스템 렌더러(`render.ts`)·Popbill 규격 일치. 변수만으로 구성 불가 → 고정 안내 문구를 충분히 둔다(전 템플릿 준수).
- **길이** 1,000자 이내(전 템플릿 여유).
- **버튼** 최대 5개. 웹링크(WL)는 `linkMo`(모바일) 필수. URL은 **고정 도메인 + 변수 토큰** 형태(카카오가 완전 변수 URL보다 선호).
- **강조표기형**은 상단 강조 `title`/`subtitle`을 별도 등록. 그 외는 **기본형**.
- **대체발송(SMS/LMS)**: 알림톡 미도달 시 대체 문구를 함께 등록 권장(각 템플릿 하단 "대체문구" 참조).
- **2차 카테고리**: 등록 시 카카오 고정 카테고리에서 선택. 전부 **안내/정보성** 계열(광고 계열 금지). 아래 각 템플릿에 권장값 표기.

**버튼 웹링크 베이스 URL** = `https://{세입자웹도메인}/r/#{상세토큰}`
- 라우트 `/r/[token]`는 확인됨(공개·무로그인·PII 제외). **도메인만 미확정**(staff는 `staff.gwanribiseo.app`; 세입자 웹 도메인은 배포 호스트 기준 확정 필요 → §5 미결 1).

## 1. 관리비 고지서  ·  강조표기형
- **대상**: 세대 입주자(주/부번호) · **진입**: `/bill` 카톡 고지서 발송
- **권장 카테고리**: 서비스 이용 > 이용안내/청구
- **강조표기**: title=`#{청구금액}원` · subtitle=`#{청구월} 관리비`

```
[#{건물명}] #{청구월} 관리비 고지서

#{세대} 세대의 #{청구월} 관리비가 발행되었습니다.

▶ 청구금액: #{청구금액}원
▶ 납부기한: #{납기일}
▶ 납부계좌: #{납부계좌}

자세한 내역은 아래 [고지서 상세보기]에서 확인하실 수 있습니다.
문의: #{관리사무소연락처}
```
- **버튼**: `[고지서 상세보기]` WL → `https://{세입자웹도메인}/r/#{상세토큰}`
- **대체문구(LMS)**: `[#{건물명}] #{청구월} 관리비 #{청구금액}원, 납부기한 #{납기일}. 상세: {단축URL}`

## 4. 민원·AS 처리 안내  ·  기본형

- **권장 카테고리**: 서비스 이용 > 접수/처리 안내

```

▶ 접수내용: #{접수내용}
▶ 처리상태: #{처리상태}
▶ 담당자: #{담당자}
```

## 3. 카카오 심사 체크리스트 (제출 전)
- [ ] 광고·홍보 문구 없음(정보성 확인)
- [ ] 변수 대비 고정 문구 비중 충분(변수만 나열 금지)
- [ ] 버튼 URL 도메인 = 사전 등록·실재 도메인(§5 미결 1)
- [ ] 강조표기형(1번) title/subtitle 등록
- [ ] 각 템플릿 2차 카테고리 선택
- [ ] 공지 3종 문구 상호 차별화(중복 반려 회피)
- [ ] 대체발송(SMS/LMS) 문구 등록 여부 결정

## 4. 배선 후속(문안 확정 이후·별도 작업)
1. 승인된 템플릿 → `message_templates`(category·channel_type='alimtalk'·`alimtalk_template_code`·`buttons`) seed/등록.
2. 발송 컨텍스트별 변수 채우기: `/bill`·`/overdue`·정산·민원·공지에서 `#{}` → 실제 값 매핑(render.ts 사용).
3. 버튼 `linkMo` 토큰 결선(`/r/[token]` 발송 시 토큰 발급).
4. 알림톡 실패 시 대체발송(SMS/LMS) 경로 설정.

## 5. 미결 (Open)
1. **세입자 웹 도메인 확정** — 버튼 베이스 URL. `/r/[token]` 라우트는 확인, 도메인만(gwanribiseo.app 루트 vs Amplify 호스트 vs resident 서브도메인).
2. **`#{상세토큰}` 발급 방식** — 고지서/공지/정산 각각 `/r/[token]`이 콘텐츠 타입을 어떻게 분기하는지(단일 토큰 라우트 확인 필요).
3. **민원·AS 대상 확정** — 세입자(처리상태) vs 담당기사(배정). 기사-배정 변형 문안 추가 여부.
4. **카카오 2차 카테고리 코드** — 등록 콘솔에서 최종 선택.
