### 마스킹 판단 기준 (사용자와 합의한 3축 — 재논의 불필요)

마스킹의 목적은 "직원에게 숨기기"가 아니라 **한 번에 많이 퍼가는 표면 줄이기**다.

1. **누구 번호인가** — 제3자(입주자·민원인·거래처)만 대상. org 소유 발신번호는 법인 자산이라 제외.
2. **읽기냐 입력이냐** — 편집 폼 input은 제외. 마스킹된 값이 저장되면 DB에 `010-****-5678`이 들어가 **데이터가 파괴**된다.
3. **한 번에 몇 건인가** — 목록·표·엑셀이 실제 유출 표면. 단건 상세는 정당한 업무 열람.

| 위치 | 처리 |
|---|---|
| 목록·표·집계 | 마스킹 + [원문] |
| 단건 상세 읽기 | 마스킹 + [원문] |
| 편집 폼 input | **원문** (마스킹 저장 = 데이터 파괴) |
| org 발신번호 (`setup/sender` 등) | **원문** (개인정보 아님) |
| 본인 정보 (세입자 내 정보, 파트너 프로필) | **원문** |
| 발송 **직전** 확인 화면 | **원문** (오발송 리스크가 더 큼) |
| 발송 **이력** 표시 | 마스킹 + [원문] |
| 엑셀·인쇄물·고지서·지로·팩스 | **원문** (대신 반출 자체를 로깅) |

마스킹 대상 필드는 **휴대폰·전화·팩스만**. 계좌번호·예금주·입주자명·차량번호는 사용자가 범위에서 뺐다.
단 `lib/privacy/mask.ts`는 kind 제네릭이라 나중에 추가 시 호출처 한 줄씩만 바뀐다.

### 브랜치가 둘로 나뉜 이유 (중요)

처음에 `discus`를 유휴로 판단해 A·B를 거기서 했는데, **실제로는 다른 세션이 동시에 쓰던 워크트리**였다.
그 세션이 discus를 master로 머지하면서 커밋 A가 같이 올라갔다. 이후 C는 유휴였던 `triggerfish`로 옮겼다.
→ **월요일에 전용 워크트리를 하나 만들어 B·C를 모으는 걸 권장.** 워크트리 생성은 사용자(Orca) 몫이다.

## 3. ⚠️ 절대 지켜야 할 순서

**마이그레이션을 적용하기 전에 C를 master로 머지하지 말 것.**
`access_log` 테이블이 없으면 `logAccess`가 실패하고, `/api/pii/reveal`은 **fail-closed 설계라 503을 반환한다**.
즉 직원이 [원문]을 눌러도 연락처를 볼 수 없어 업무가 막힌다. 머지 = Amplify 프로덕션 자동 배포다.

B(공개링크)는 예외적으로 안전하다. 커밋 `8967dede`에서 `issued_day`가 없으면 URL에 `d`를 안 붙이고
검증기의 4-arg 레거시 경로를 타도록 해뒀다. 코드가 먼저 배포돼도 현행 동작을 유지하고,
마이그가 적용되는 순간 30일 규칙이 활성된다.

권장 순서: **마이그 0174 → 0175 → (C2 검증 후) 0176 적용 → 그다음 머지·push.**

## 4. 월요일 확인사항

### 반드시 사람이 확인해야 하는 것

1. **PostgREST 오버로드 해석** — 0175가 `public_bill_by_signed`를 4-arg/5-arg 두 개로 만든다.
   PostgREST는 인수 **이름 집합**으로 함수를 고르는데, 모호하면 `PGRST203`이 난다. DB 없이는 검증 불가.
   → 0175 적용 후 **레거시 링크(`?s=...`, `d` 없음) 1건**과 **신규 링크(`?s=...&d=...`) 1건**을 실제로 열어볼 것.
2. **C2 마스킹이 업무를 막지 않는지** — 특히 원문이 필수인 경로가 마스킹되지 않았는지:
   편집 폼 / 발신번호 설정 / 발송 직전 확인 화면 / 고지서·지로 인쇄 / 팩스 / 엑셀 6종 / 세입자 본인 정보 / 파트너 본인 프로필.
3. **[원문] 버튼 동작** — 사무실 직원·현장 파트너 각각으로 눌러보고, 파트너가 **담당 건물 밖** 입주자는 못 여는지(RLS) 확인.
4. **`access_log`에 행이 쌓이는지** — 원문 보기 1회 후 `select * from access_log order by id desc limit 5`.

### 미결 정책 (사용자 결정 필요)

- **감사 로그 보존기간** — 미정. 개인정보보호법상 접속기록 최소 1년(규모에 따라 2년). purge 잡 없음.
  `access_log`에 `created_at` 인덱스는 미리 깔아둠.
- 계좌번호·예금주·입주자명·차량번호 마스킹 — 이번 범위에서 제외됨. 추가할지 결정 필요.

- **D 착수**: 엑셀 반출 6종(`buildings/export`, `customer-numbers/export`, `fee-items/export`, `payment/cms`,

  반출은 `rowCount`를 채울 것. **PII_REVEAL만 fail-closed이고 나머지는 fail-open** — 로그 실패가 업무를 막으면 안 된다.
