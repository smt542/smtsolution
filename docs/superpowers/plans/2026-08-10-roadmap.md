# 관리비서 구현 로드맵

> **작성일**: 2026-08-10  
> **기준 문서**: `docs/superpowers/specs/2026-08-10-prd-synthesis.md` (단일 정본)  
> **범위**: Staff PC 웹 우선. 모바일·세입자 앱은 별도 후속 트랙.  
> **상태**: 계획 단계 — 각 단계별로 별도 spec→plan 문서 작성 예정.

---

## 1. 개요

### 목표
레거시 주택관리 시스템을 Next.js 16 App Router + Supabase + React Query 기반으로 현대화.  
Staff(사무실 PC) 화면 전체를 P2~P8로 완성하고, 이후 모바일·세입자 앱으로 확장.

### 원칙

| 원칙 | 내용 |
|---|---|
| **PRD 정본 기준** | `prd-synthesis.md` §B~§E가 유일한 설계 기준. 개별 prd/*.md는 세부 확인 용도. |
| **의존성 순서** | 권한(P2) → 도메인(P3) → 공용 발송(P4) → 부과(P5) → 수납(P6) → 이사(P7) → 대시보드 실데이터(P8). 순서 변경 금지. |
| **문자모듈 공용화** | `/messaging` 엔진(P4)을 먼저 구축. P5~P7 화면은 컨텍스트 프리셋 방식으로 호출만 함. |
| **권한 RLS 강제** | P2에서 module-permission RLS를 민감 테이블에 적용. 이후 모든 새 테이블에 동일 패턴 적용. |
| **소프트삭제·이력 보존** | 계정 비활성화(삭제 금지), 입주 이력 누적, 발송 이력 보존. `deleted_at` 컬럼 패턴 유지. |
| **금액 정수·우수리 처리** | 모든 금액 컬럼 `integer`(원 단위). 일할계산·연체료 계산 시 소수점 이하 처리 규칙을 각 단계 spec에서 확정. |
| **감사로그 확장** | 기존 `audit_log` 테이블을 권한 변경·부과 확정·수납 처리 등 주요 액션에 지속 확장. |

## 3. 단계별 로드맵

### P2 — 계정·권한 & 셋업 (관리 기반)

**목표**: 모든 권한 게이팅의 실질적 기반을 완성하고, 이후 단계가 참조할 전역 설정값을 관리.

**포함 화면**

| 라우트 | 설명 |
|---|---|
| `/staff/accounts` | 4가지 계정 유형(관리자/직원/현장직원/스태프) 등록·수정·비활성화, 기능별 권한 체크리스트(10항목), 마스터 직원만 권한 변경 |
| `/staff/setup` | 5탭: 고지서설정 / 계좌설정(최대2개) / 이사정산설정 / 시스템설정 / 장기수선비 |

**신규/변경 DB 도메인**

- `org_members` — `staff_type`(field_staff / staff / admin / employee) 컬럼 추가, `feature_permissions` jsonb 키 목록 정규화
- `staff_roles` — 담당역할(관리·검침·청소) 마스터; 건물 담당자 배정 연결용
- `setup_config` — 조직별 고지서·계좌·이사정산·시스템 설정 (단일 행 upsert 패턴)
- `room_types` — 룸타입 마스터 (시스템설정 탭 관리)
- `septic_vendors` — 정화조업체 마스터
- `as_categories` — AS 구분 명칭 마스터
- `cleaning_teams` — 청소팀 마스터
- `quick_messages` — 자주 보내는 문자 마스터
- `long_term_repair_history` — 건물별 장기수선비 공사 이력 (파일 첨부 포함)

**주요 규칙·결정** (§E)

- 계정 삭제 금지 → 비활성 처리로 이력 보존 (2026-07-14)
- 입주자 계정 생성은 `/accounts` 불가 → 입주자 상세에서만 생성; `/accounts`는 조회·발급·비활성만 (2026-07-14)
- 기능별 권한은 등급이 아닌 체크리스트 방식; 마스터 직원만 변경 가능 (2026-07-14)
- 관리비 입금계좌 최대 2개, 각 출력/미출력 선택 (2026-07-13)
- 시스템설정 탭 내 직원 계정·담당자 관리 → `/accounts`로 이관됨 (2026-07-14)
- **module-permission RLS 적용**: 민감 테이블(setup_config 등)에 `feature_permissions` jsonb 검사 RLS policy 추가
- 현재 `/staff/vendor-management` 독립 화면 → `/setup` 시스템설정 탭으로 통합 (PRD 정본 위치)

**의존성**: P0(RLS 패턴), P1a(vendors 등 마스터 재활용)  
**대략 규모**: L (RLS policy 설계 + Edge Function 프로비저닝 + 5탭 폼)

### P3 — 건물·입주자 (도메인 코어)

**목표**: 건물 상세 5섹션 + 입주자 등록·상세를 PRD 정본 라우트 구조로 완성.

**포함 화면**

| 라우트 | 설명 |
|---|---|
| `/staff/buildings` | 건물 목록 (필터: 관리·검침·청소 담당자, 엑셀 다운) |
| `/staff/buildings/new`, `/staff/buildings/:id` | 건물 등록·상세 5섹션(기본정보/시설/고객번호/협력업체/참고사항) |
| `/staff/buildings/:id/tenants` | 입주자 목록 (탭, 출력 버튼 2종) |
| `/staff/buildings/:id/tenants/new` | 입주자 등록 |
| `/staff/buildings/:id/tenants/:tenantId` | 입주자 상세 5섹션 |

**신규/변경 DB 도메인**

- `building_customer_numbers` — 수도/공용전기/전기/가스 고객번호 다중 등록 (검침일/부과기간/명의자 포함)
- `occupancies` — `move_in_expected_date`(입주예정일), `deposit_payer_name`(입금자명), `contacts` 3개, `vacancy_flag`, `billing_note`, `settlement_note` 컬럼 추가·확인
- `unit_meters` — 세대별 계량기번호·고객번호 (수도·전기·가스)
- `unit_accounts` — 세대별 수도·전기·가스·관리비 입금계좌 (CMS 회원번호 포함)
- `lease_contracts` — 보증금/월세/계약기간/만료알림 임대차 정보
- `occupancy_history` — 전출자 퇴실 시 자동 누적 저장 (입주 이력)
- `room_types` — P2에서 생성; P3에서 occupancies에 FK 연결

**주요 규칙·결정** (§E)

- 건물 기본 정렬: 등록일 최신순, 페이지네이션 10/20/50건(기본20) (2026-07-03)
- 신규·수정 하나의 화면에서 모드 분기 (2026-07-03)
- 고객번호 복수 등록 가능, 협력업체 파일 업로드 수 제한 없음 (2026-07-03)
- 입주자카드·관리비부과내역서 출력 버튼: 입주자 목록 섹션 상단에 위치 (2026-07-16)
- 룸타입: 사전 등록 목록 드롭다운(P2 room_types 참조) (2026-07-03)
- 입주자 계좌: 수도·전기·가스·관리비 각각 별도 입력 (2026-07-03)
- 입주예정일(미래 입주일) → 대시보드 팝업 트리거 데이터 (P8에서 소비) (2026-07-13)
- 전출자 이력: 퇴실 시 자동 누적 저장, 입주자 상세에서 읽기전용 노출 (2026-07-03)

**의존성**: P2(room_types, staff_roles 드롭다운), P1a(buildings/units/occupancies 기반)  
**대략 규모**: L (계층 라우트 재구성 + 5섹션 × 2화면 + 다중 신규 엔티티)

### P4 — 문자·알림톡 공용 모듈 (`/messaging`)

**목표**: 고지서·독촉·정산·민원 발송을 단일 엔진으로 통합. P5~P7이 컨텍스트 프리셋 방식으로 호출.

**포함 화면**

| 라우트 | 설명 |
|---|---|
| `/staff/messaging` | GNB 독립 진입: 템플릿 선택 / 수신처 선택 / 즉시·예약 발송 / 발송 이력 |
| *(hook)* | 타 화면에서 프리셋 파라미터로 호출되는 공용 훅/모달 |

**신규/변경 DB 도메인**

- `message_logs` — 발송 이력 (발송자/일시/수신처/채널SMS·알림톡/내용/결과/NCP 응답코드)
- `message_templates` — NCP 등록 알림톡 템플릿 ID 참조 + 자유본문 템플릿 (고지서/독촉/정산내역서/민원AS/공지3종)
- `scheduled_messages` — 예약 발송 큐 (발송일시/취소여부)
- `quick_messages` — P2에서 생성; P4에서 발송 모듈 템플릿으로 연동

**주요 규칙·결정** (§E)

- 흩어진 개별 발송 → 공용 발송 모듈 통합; 각 화면은 프리셋 전달 방식 호출 (2026-07-14)
- 예약 발송: 기간·횟수 제한 없음, 등록 후 취소 가능 (2026-07-14)
- 발송 수신처 인물 연락처는 `/accounts`에서 관리 (2026-07-14)
- NCP SMS/알림톡 API 연동; 실패 건 재발송 UI 필요
- 컨텍스트 프리셋 6종 정의: 고지서(알림톡)/고지서(SMS)/민원AS안내/독촉/정산내역서/공지

**의존성**: P2(accounts 연락처), P3(세대·건물 수신처 목록)  
**대략 규모**: M (NCP API + 스케줄러 + 프리셋 훅 설계가 핵심)

### P5 — 검침·부과·고지서

**목표**: 지침 입력 → 요금 계산 → 부과 확정 → 고지서 발행의 월말 업무 플로우 완성.

**포함 화면**

| 라우트 | 설명 |
|---|---|
| `/staff/utilities` | 건물별 수도·전기·가스 지침 입력, 세대별 요금 자동 계산, 6개월 이력 팝업 |
| `/staff/management-fee` | 관리비 항목 관리(이월Y/N), 세대별 금액 입력, 부과 확정 |
| `/staff/bill` | 지로·A4·카톡·팩스 발행·발송, 그룹별 분리 출력, QR코드 |

**신규/변경 DB 도메인**

- `meter_readings` — 세대별 월별 수도·전기·가스 지침 이력 (전월·당월·사용량·계산요금·수동요금·적요)
- `water_discounts` — 수급자·다자녀 할인 설정 (세대별)
- `fee_item_charges` — 관리비 항목별 세대 금액 (이월 처리 포함)
- `billing_confirmations` — 부과 확정 테이블 (세대별·월별·확정일시·확정자)
- `billing_history` — 부과 이력 (6개월 이력·전월대비 증감 계산용)
- `bill_issues` — 고지서 발행 기록 (발행유형/그룹/납기일/자동이체여부/발송상태)
- `fee_items` — 기존 테이블에 `carry_over`(이월여부) 컬럼 추가

**주요 규칙·결정** (§E)

- 고지서 세대 표기: 코드출력/이름출력 선택 (전역 기본값 + 발행 시 건별 재지정) (2026-07-13)
- 조정명세서·자동이체 세대 출력: 그룹별 분리 출력 (납기일·출금신청일 상이 대응) (2026-07-13)
- 출력 화면에서 단수 표기·해지 설정 및 납기일 자유 변경 가능 (2026-07-13)
- 카톡 고지서: P4 발송 모듈 컨텍스트 호출 (알림톡 프리셋)
- 신규 입주자 당월 부과 팝업: 부과 확정 후 신규 등록 시 자동 노출
- 공실 세대 지침 입력 비활성, 신규 입주 행 파란색 강조

**의존성**: P2(권한 게이팅·setup_config), P3(세대·계량기·고객번호), P4(발송 모듈)  
**대략 규모**: L (계산 로직 복잡성 + 출력 레이아웃 3종 + 부과 확정 트랜잭션)

### P6 — 수납·미납

**목표**: 수납 수동·자동 처리, 민원 접수·관리, 미납 채권 필터·독촉 발송.

**포함 화면**

| 라우트 | 설명 |
|---|---|
| `/staff/payment` | 수납 수동 처리(전액/원금/취소/분할), 지로 수납, 엑셀 자동 매칭, 효성CMS 워크플로우 |
| `/staff/receipts` | 수납현황 조회 + 민원·AS 접수·처리 통합 (AS접수현황 팝업 포함) |
| `/staff/overdue` | 미납 조회, 채권 필터(3개월↑ AND 10만↑), 독촉 문자, 미납대장 출력 |

**신규/변경 DB 도메인**

- `payments` — 수납 테이블 (부과대비 수납현황, 유형: 전액/원금/취소/분할, 수납일시)
- `giro_payments` — 지로 수납 테이블 (지로 고유번호, 원장 참조)
- `complaints` — 민원·AS 테이블 (접수일/건물·호실/내용/상태: 미결·완결·보류·반복/처리결과/담당기사/사진)
- `overdue_snapshots` — 미납 채권 계산용 스냅샷 또는 뷰 (연체개월수·미납금액 집계)

**주요 규칙·결정** (§E)

- 효성CMS: 회원번호 등록 → 엑셀다운(오름차순) → 청구금액 붙여넣기; CMS API 직접 연동 제외 (2026-07-13)
- 엑셀 자동 매칭: 고객번호→이름→금액 순 3단계, 미매칭 수동 처리
- 채권 관리 필터 기준: 연체 3개월↑ AND 10만원↑ (고정값, 변경 불가) (2026-07-03)
- 단전·단수 예고: 연체 2개월↑ → 3개월째 고지서 시 자동 인쇄 (별도 설정 없음) (2026-07-03)
- 독촉 문자: P4 발송 모듈 컨텍스트 호출 (독촉 프리셋)
- 민원 담당 기사 문자: P4 발송 모듈 컨텍스트 호출 (민원AS안내 프리셋)
- 수납명세서·영수증 출력: PDF 생성 필요

**의존성**: P4(발송 모듈), P5(billing_confirmations — 부과금액 기준)  
**대략 규모**: L (3개 화면 + CMS 워크플로우 + 민원 상태머신 + 채권 집계 쿼리)

### P7 — 이사정산 (`/moving-settlement`)

**목표**: 퇴실 세대 정산 계산·저장·출력, 중도퇴실·공실 처리, 입주 이력 자동 누적.

**포함 화면**

| 라우트 | 설명 |
|---|---|
| `/staff/moving-settlement` | 건물→호실 선택, 정산 입력·계산, 중도퇴실/정산완료+공실 버튼, 이력 조회 |

**신규/변경 DB 도메인**

- `moving_settlements` — 이사정산 테이블 (퇴실일자/관리비일할/지침값/수리비/귀속/정산금/계좌/비고/적요)
- `settlement_checklist_results` — 세대별 내부 시설점검 체크리스트 결과 (setup_config 체크항목 참조)
- `occupancy_history` — P3에서 생성; 정산완료+공실 시 자동 INSERT
- `payments` — P6에서 생성; 정산완료+공실 시 미납 수납 확인 및 연동

**주요 규칙·결정** (§E)

- 정산완료+공실: 미납 수납 확인팝업 → 수도 지침 자동이월 → 적요 리셋 → occupancy_history 누적 저장
- 중도퇴실: 공실 처리 없음, 종이고지서→카톡 자동 변경, 수납적요 "중도퇴실" 자동 기재
- 좌측 검침정보 패널(수도·전기·가스 전·당월 지침): 상시 표시, 읽기전용
- 정산내역서 문자: P4 발송 모듈 컨텍스트 호출 (정산내역서 프리셋, 모바일에서도 동일)
- 이사정산 설정(단가 반영여부·공실처리 수납방식·체크항목): P2 setup_config 탭③ 참조

**의존성**: P2(setup_config 이사정산 탭), P3(occupancy_history 테이블), P5(meter_readings), P6(payments)  
**대략 규모**: M (단일 화면이지만 다수 테이블 조인 + 정산 계산 로직 + 상태 전환)

### P8 — 부가·대시보드

**목표**: 대시보드 실데이터 연결, 입주예정일 팝업, 공지사항, 장기수선비 이력 화면.

**포함 화면**

| 라우트 | 설명 |
|---|---|
| `/staff` (대시보드) | 실데이터 카드(입주예정·미처리AS·미납세대 수), 입주예정일 팝업 |
| `/staff/notices` | 건물별 공지사항 목록·등록·상세 (신규·중요·긴급 구분, 알림톡 발송 연동) |
| *(setup 탭⑤)* | 장기수선비 이력 — P2 `/setup` 탭⑤에 이미 배치; 실데이터 연결만 |

**신규/변경 DB 도메인**

- `notices` — 공지사항 테이블 (건물별/유형: 신규·중요·긴급/딥링크/알림톡발송여부)
- `dashboard_popup_dismissals` — 입주예정일 팝업 "오늘 그만보기" 사용자별 날짜 저장
- `long_term_repair_history` — P2에서 생성; 대시보드 요약 연결

**주요 규칙·결정** (§E)

- 로그인 후 첫 진입 화면 = 대시보드(`/`) (2026-07-14); 현재 receipt-management 리다이렉트 → 수정 필요
- 입주예정일 팝업: `닫기`(당일 재노출) / `오늘 그만보기`(당일 자정까지 미노출) (2026-07-14)
- 공지 알림톡: 신규·중요·긴급 3종 템플릿, [공지확인하기] 딥링크 포함 (2026-07-13)
- 대시보드 업무 요약 표시 항목은 P8 spec 시 확정 (현재 PRD 미확정)

**의존성**: P3(occupancies 입주예정일), P5(billing_confirmations), P6(complaints·payments), P4(알림톡 발송)  
**대략 규모**: S (신규 로직 적고 기존 데이터 집계·연결이 주)
