## Task 10: #31 전월과수납 자동 처리

요구: 입금액이 미납보다 많으면 초과분을 과수납으로 기록하고 다음 달 고지서에 "전월과수납" 항목(음수)으로 자동 차감한다. 항목등록에 "전월과수납" 고정 항목(이름 수정·삭제 불가). 조사: research/item31.md, 대응필수.md #31 (개선 방안 1~6 단계가 설계).
- 사용자 결정: 전체 구현 — 과수납 원장 + 전월과수납 시스템 항목 + 익월 자동 차감 + 한 번 입금으로 여러 달 미납을 오래된 달부터 배분. 기존 초과 수납 데이터(2026-07~10, 약 22세대)는 백필하지 않는다.
- Ruling(연체료 구분): 초과분 = 그 달 수납 합계 − (당월계 + 그 달 연체료[서버 기준 계산, 수동 override 우선]). 연체료 한도 내 초과는 연체료 수납으로 본다. `paymentHistoryRows.collectedLateFeeForRow` 도 `min(-unpaid, 그 달 연체료)` 로 제한하고 나머지를 과수납으로 표시.
- Ruling(차감 범위): 같은 occupancy 의 open 과수납 누적 잔액 전부를 다음 확정 고지서에서 차감하되 그 달 다른 항목 합계를 넘지 않게(total ≥ 0), 남은 잔액은 다음 달로 이월. 재확정 시 멱등.
- Ruling(배분): 여러 달 배분은 수납관리 화면의 기존 수납 입력 흐름에 옵션으로 붙이지 않고, 서버 RPC 가 "선택한 달의 미납을 넘는 금액"을 같은 세대의 더 오래된 미납 달부터 별도 payments 행으로 나눠 기록한 뒤 남는 금액만 과수납으로 둔다. UI 변경이 필요하면 기존 확인 다이얼로그 문구 수준으로 한정.
