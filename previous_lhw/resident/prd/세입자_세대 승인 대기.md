## 1. 목적

사용자가 직접 입력한 **세대 연결 요청이 관리주체(관리사무소) 승인을 기다리는** 대기 화면. 승인되면 이 화면에서 **자동으로 홈**으로 전환된다.

---

## 2. 권한

| 사용자 | 접근 |
|---|---|
| resident (승인 대기 사용자) | O — 대기 안내 조회 + 문의 전화 / 로그아웃 |

- 세대 연결의 **승인 주체는 관리주체(staff)**. 세입자는 대기·문의만 한다.

---

## 3. UI

### 3.0 안내
- **기능**: 요청 접수 안내.
- **규칙**: 제목 "확인 요청을 보냈어요" + 부제 "관리사무소에서 세대를 확인하면 알림으로 알려드려요. 보통 **1영업일** 안에 처리돼요".

### 3.1 요청 정보 카드
- **기능**: 제출한 요청 요약.
- **규칙**: **요청 세대**(예: 그린빌라 201호) · **요청 일시**(예: 2026.08.07 15:53) 표시(읽기).

### 3.2 문의 안내
- **기능**: 급할 때 직접 문의.
- **규칙**: "급하면 바로 문의하세요" + **관리주체명 · 전화번호**(예: 스마일종합관리 · 042-822-4410), **전화 걸기(`tel:`) 링크**. 관리주체 연락처는 세대의 관리주체 기준으로 표시.

### 3.3 하단 버튼
- **기능**: 세션 종료.
- **규칙**: **「로그인 화면으로」 = 로그아웃**(세션 종료 → `resident-login`). **연결 요청 자체는 유지**된다(취소 아님).
  - `❓` 프로토타입 전용 "테스트: 승인되었다고 가정하고 홈으로" 버튼은 **실제 앱에서 제외**.

### 3.4 승인 감지 · 자동 전환
- **기능**: 승인 시 자동 진입.
- **규칙**:
  - 관리주체가 승인하면 **알림(카카오/푸시)으로 통지**하고, **이 대기 화면에서 자동으로 홈(`resident-home`)으로 전환**된다.
  - **승인 전 앱을 다시 열면 이 대기 화면으로 고정**(로그인된 상태로 pending 유지).

---

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 대기 | 요청 접수·미승인 | 요청 정보 + 문의 + 로그아웃 |
| 승인됨 | 관리주체 승인 | 알림 통지 + 자동으로 홈 전환 |

- **반려(거부) 개념은 없다** — 잘못된 요청은 관리주체가 **승인하지 않고 무시**하며, 이 경우 화면은 **대기 상태로 지속**된다(사용자는 문의로 해결).

---

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 요청 세대·일시 | 세대 연결 요청 데이터 | 진입 시 |
| 관리주체 연락처 | 건물·관리주체 데이터([_data-dictionary.md](../../_data-dictionary.md) B) | 문의 표시 |
| 승인 상태 | 매칭·승인 데이터 | 승인 감지 시 자동 전환(폴링/푸시) |

- **발송**: 승인 시 사용자에게 알림 통지(카카오/푸시) — 관리주체 처리 결과 안내.
