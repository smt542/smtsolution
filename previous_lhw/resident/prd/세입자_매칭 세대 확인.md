## 1. 목적

자동 매칭된 세대가 **본인 세대가 맞는지 확인**받는 화면. 맞으면 세대 연결을 확정하고 알림 설정(`resident-notify`)을 거쳐 홈으로, 아니면 **직접 건물·호수를 입력**해 관리사무소 확인(`resident-pending`)으로 보낸다.

---

## 2. 권한

| 사용자 | 접근 |
|---|---|
| resident (세대 미확정 사용자) | O — 확인/거부 및 직접 세대 찾기 |

- 확인 대상 세대 정보는 **관리주체(관리사무소)가 등록한 자료** 기준(세입자는 수정 불가).

---

## 3. UI

### 3.0 헤더/안내
- **기능**: 확인 요청 안내.
- **규칙**: 제목 "이 세대가 맞나요?" + 부제 "카카오에 등록된 연락처로 찾은 세대예요. 확인하면 관리비 내역을 바로 볼 수 있어요".

### 3.1 매칭 세대 카드 (읽기)
- **기능**: 매칭된 세대 정보 표시.
- **규칙**:
  - 표시: **이름 · 전화번호 · 건물 · 호수 · 입주일 · 관리주체**([_data-dictionary.md](../../_data-dictionary.md) C).
  - **개인정보 마스킹 유지**: 이름 가운데 마스킹(예: `박O호`), 전화번호 중간자리 마스킹(예: `010-****-7788`).
  - 하단 안내: "세대 정보는 관리사무소에 등록된 자료를 기준으로 확인해요".

### 3.2 하단 버튼
- **기능**: 확인/거부.
- **규칙**:
  - **「네, 맞아요」** → 세대 연결 **확정** → 알림 설정(`resident-notify`)로 이동(이후 "시작하기" → 홈).
  - **「제 세대가 아니에요」** → 3.3 **직접 찾기 바텀시트** 오픈.

### 3.3 세대 직접 찾기 바텀시트 (2단계)
- **기능**: 매칭이 틀렸을 때 사용자가 직접 건물·호수를 지정.
- **규칙**:
  - **1단계 — 건물 찾기**: "어느 건물에 사시나요?" 건물명/주소 **검색**(placeholder "예: 그린빌라 · 봉명동"). **관리 중인 건물 목록**에서 선택. 부정확해도 동 이름·주소 일부로 재검색 가능.
  - **2단계 — 호수 입력**: "호수를 입력해 주세요" **숫자 입력**(예: 201). 지하 등 비정형(예: `B101`)은 "관리사무소 확인이 필요"하다고 안내.
  - 제출 → "관리사무소 확인 후 세대를 연결해 드려요" → **`resident-pending`(승인 대기)** 로 이동.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 기본 | 매칭 성공 진입 | 확인 카드 + 두 버튼 |
| 직접 찾기 | "제 세대가 아니에요" | 바텀시트(건물 검색 → 호수 입력) |
| 확정 | "네, 맞아요" | 세대 연결 확정 → 알림 설정 이동 |
| 대기 | 직접 입력 제출 | 관리사무소 확인 대기(`resident-pending`) |
