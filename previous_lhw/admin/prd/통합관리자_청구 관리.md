## 1. 목적

월별로 **테넌트별 발송비 청구서를 발행**하고 **입금 상태를 관리**하는 화면. 각 테넌트가 그 달 발송(알림톡·문자·팩스)한 만큼 청구한다.

---

## 2. 권한

| 사용자 | 접근 |
|---|---|
| admin (본사 관리자) | O — 청구 조회 · 청구서 발행 · 입금 상태 처리 |

- 입주자 개인정보는 다루지 않고 **테넌트 청구 정보**만.

---

## 3. UI

### 3.0 헤더 + 월 선택
- **기능**: 제목 + 청구 월 선택.
- **규칙**: "청구 관리" + **월 선택**(예: 2026년 8월).

### 3.1 요약
- **기능**: 당월 청구 요약.
- **규칙**: 당월 **총 청구액** · **미입금액** · **미입금/입금 곳수**(예: 미입금 7곳 · 입금 4곳). 채널 합계(알림톡·문자·팩스 **건수**).

### 3.2 필터 + 전체 발행
- **기능**: 상태 필터 + 일괄 발행.
- **규칙**: `전체` / `미입금` / `입금` / `청구 없음`. **「전체 발행」** → 전 테넌트 청구서 일괄 출력.

### 3.3 테넌트별 청구 표
- **기능**: 업체별 청구·입금 관리.
- **규칙**:
  - 컬럼: **업체명 · 이메일 · 알림톡 · 문자 · 팩스 · 청구액 · 전월비 · 상태 · 처리**. 페이지네이션.
  - **청구액 = 채널별 발송 건수 × 채널별 청구 단가**(대시보드·포인트 소진과 동일 소스).
  - **상태**: `입금완료` / `미입금` / `청구 없음`.
  - **처리 버튼**:
    - **발행** — 해당 테넌트 **청구서 출력**.
    - **입금 확인** — 미입금 → 입금완료(**수동 상태 토글**, 실결제 무관).
    - **입금 취소** — 입금완료 → 미입금.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 성공 | 청구 있음 | 요약 + 목록 |
| 결과 없음 | 필터 결과 0곳 | 없음 안내 |
| 로딩/에러 | 조회 중·실패 | 공통 표준 준용 |

---

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 월별 테넌트 발송량·청구액 | 발송 데이터(대시보드·`admin/points` 소진과 동일 소스) | 월 선택 시 |
| 입금 상태 | 청구·입금 데이터 | 입금 확인/취소 시 |
| 청구서 | 청구서 출력 | 발행/전체 발행 |

- 발송 트리거 없음(청구서 출력은 문서 생성). 입금은 수동 상태 관리(실결제 아님).
