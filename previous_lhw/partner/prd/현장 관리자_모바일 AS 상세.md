## 1. 목적

현장관리자가 본인 할당 A/S **1건의 상세를 확인·수정**하고, **처리결과(상태·시행일자·시간·처리내용)를 기록·저장**하거나 접수를 **삭제**하는 화면.

---

## 2. 권한

| 사용자 | 접근 |
|---|---|
| partner (현장관리자) | O — **본인 A/S 수정·저장·삭제**(쓰기) |
| staff / resident | — (별도 표면) |

- partner의 쓰기 가능 영역인 **본인 A/S 처리**에 해당([_permission-matrix.md](../../_permission-matrix.md) 3절, [_service-policy.md](../../_service-policy.md) 2.3).
- 삭제는 되돌릴 수 없는 액션 → **확인 모달** 필수([_permission-matrix.md](../../_permission-matrix.md) 6절).
- **발송 없음**(A/S 확인 문자는 staff `receipt-management` 소관, partner는 발송하지 않음 — [_notification-policy.md](../../_notification-policy.md) 3절).

## 3. UI

### 3.0 상단 헤더
- **기능**: 뒤로가기 + 제목("A/S 상세").
- **규칙**: 뒤로가기 → `mobile-home`.

### 3.1 대상 세대 (읽기)
- **기능**: 건물·호수 표시.
- **규칙**: 접수 데이터의 건물명에서 건물/호수 분리 표시(읽기 전용). "건물 전체" 접수는 호수 대신 표기.

### 3.2 A/S 내용
- **기능**: 접수 정보 확인·수정.
- **규칙**:
  - 읽기: **접수자 · 담당자 · 접수일시 · 입주자 전화번호**.
  - 수정: **유형**(드롭다운, [_status-codes.md](../../_status-codes.md) 1절 A/S 유형) · **접수 내용**(textarea, 저장 시 필수).
  - 드롭다운은 커스텀 드롭다운 규칙 준수(`CLAUDE.md`).

### 3.3 처리
- **기능**: 처리결과 기록.
- **규칙**:
  - **처리결과(상태)**: 드롭다운 `미결·보류·완결·반복`([_status-codes.md](../../_status-codes.md) 1절).
  - **시행일자**: **달력**으로만 선택([_service-policy.md](../../_service-policy.md) 5절 날짜 입력 통일).
  - **시간**: HH:MM 숫자 입력(00~23:00~59 보정).
  - **처리결과 내용**: textarea.

### 3.4 하단 액션
- **기능**: 삭제 / 저장.
- **규칙**:
  - **저장**: 접수 내용 비어 있으면 차단·안내. 확인 모달 후 저장, 완료 토스트 → `mobile-home` 복귀.
  - **삭제**: 확인 모달(되돌릴 수 없음 안내) 후 삭제, 완료 토스트 → `mobile-home` 복귀.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 성공(조회) | 상세 로드 | 필드 채워 표시 |
| 검증 | 접수 내용 미입력 | 저장 차단 + "접수 내용을 입력해 주세요" |
| 확인 | 저장·삭제 시도 | 확인 모달 |
| 성공(저장/삭제) | 처리 완료 | 토스트 후 홈 복귀 |
| 에러 | 저장·삭제 실패 | 실패 안내·재시도(공통 표준, 원본 훼손 금지) |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| A/S 상세 | 민원·A/S 데이터([_data-dictionary.md](../../_data-dictionary.md) H절) · 프로토타입 localStorage | 진입 시 로드 |
| 저장/삭제 | 동일 소스 | 저장·삭제 버튼(모달 확인 후) |

- 발송 트리거 **없음**. 저장·삭제는 감사 로그 대상(주요 데이터 변경, [_service-policy.md](../../_service-policy.md) 8절, 시스템 자동 기록).
