## 1. 목적

관리업체 직원이 **기존 건물의 기본정보·협력업체·건물주·공과금 고객번호 등 전체 정보를 조회·수정**하거나, 건물을 삭제하는 화면.

## 3. UI (섹션 순서)

### 3.0 상단 헤더
- **기능**: 건물명 표시 + 저장 / 목록으로.
- **규칙**: 좌측 크럼("건물·입주자 관리")·건물명 제목. **저장**=전체 섹션 통합 저장(섹션별 개별 저장 없음). **목록으로**=입력 변경 시 이탈 확인 모달 후 `building-list` 이동. 공통 LNB/RNB 공유.

### 3.1~3.6 폼 6섹션 (등록과 동일)
동일 구조·필드 규칙은 [building-register.md](../building-register/building-register.md) 3절 참조. 요약:
1. **기본 정보** — 건물 코드* · 건물명 · 건물 유형 · 공동현관 · 주소*(주소검색) · 고지서 부과 그룹 유형(1~5) · **수도 고객번호 보유 수(1~8·10, 9 결번)** · 계약일 · 해지일 · **건물 상시 공지문**.
   - **건물 상시 공지문**: 입력 시 **세입자 앱 홈의 건물 공지에 상시 노출**, 비우면 미표시(→ resident 앱 연동).
2. **업체 및 담당자 지정** — 사무 담당자* · 현장 관리자* + 9종 협력업체 블록(청소·정화조·인터넷·전기안전·유선방송정보·승강기보수·승강기정기검사·소방검사·CCTV). 공통 `업체명·전화·계좌·계약서 사진(최대 10)·비고` + 구분별 추가 필드. **협력업체는 마스터(`vendor-management`)에서 선택 배정** 후 건물별 계약 상세 입력([vendor-management.md](../vendor-management/vendor-management.md)).
3. **적립금** — 유형(적립금·장기수선충당금·기타·없음)·메모. 실제 입출금은 `long-term-repair`.
4. **건물주 정보** — 건물주명·전화(주/부)·주소(주소검색)·비고.
5. **부가 정보(공과금 고객번호)** — 수도/공용전기/전기/가스 블록. 각 `고객번호·성명/계약자·입금·월분(당월/전월)·계산(자동/수동)·계산법·이체·조회·검침일(1~31)·고지기간(당월/전월/전전월)·고지기간 출력(Y/N)·메모` + 가스 `가스회사·가스전화·계좌번호` + `부과시 참조사항`. **공용전기는 축소형**(계산법·고지기간 출력 없음). `＋고객번호 추가`로 증설.
6. **건물 메모** — 자유 메모(최대 1,000자).

### 3.7 건물 삭제
- **기능**: 건물 삭제(되돌릴 수 없음).
- **규칙**: 확인 모달을 거친다([_permission-matrix.md](../../_permission-matrix.md) 6절). 삭제 후 `building-list`로 이동. **부과·수납 이력이 있는 건물은 삭제 시 '과거 데이터 영향' 경고 후 진행**한다(완전 차단은 아님, 과거 데이터는 보존; fee-item 삭제 정책 준용).

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 로딩 | 진입 시 데이터 조회 중 | 로딩 표시([_service-policy.md](../../_service-policy.md) 6절) |
| 조회/수정 | 데이터 로드 완료 | 값이 채워진 폼 |
| 검증 실패 | 필수 미입력(건물 코드·주소·사무 담당자·현장 관리자) | 해당 필드 안내, 저장 차단 |
| 성공 | 저장 완료 | 토스트 |
| 이탈 확인 | 변경 후 목록 이동 | "저장하지 않고 나가시겠습니까?" 모달 |
| 삭제 확인 | 건물 삭제 클릭 | 확인 모달(이력 보유 시 경고) |
| 에러 | 조회·저장 실패 | 실패 안내·재시도 |
