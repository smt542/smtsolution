## 1. 목적

관리업체(테넌트)의 시스템 사용 계정을 등록·관리하는 화면이자, **staff 권한 부여의 정본 화면**이다. 마스터가 사무실 관리자·현장 관리자 계정을 만들고 **계정별로 LNB 항목 접근권한(페이지별 권한 칩)** 을 부여하며([_permission-matrix.md](../../_permission-matrix.md) 2절과 정합), 입주자 탭에서 **카카오 계정 ↔ 세대 연결**(매핑실패 수동연결)을 처리한다.

## 2. 권한  ([_permission-matrix.md](../../_permission-matrix.md) 2절)

| 사용자 | 접근 |
|---|---|
| staff (마스터) | O — 계정 등록·수정·권한 부여의 정본 |
| staff (일반) | LNB "계정·직원" 권한 부여 시 O (계정별 설정형) |

- 계정별 **LNB 항목 접근권한 부여/제한은 마스터**가 이 화면에서 수행한다(테넌트 최상위 계정). 일반 계정은 부여된 LNB 항목만 노출·접근한다([_service-policy.md](../../_service-policy.md) 2.3, [_permission-matrix.md](../../_permission-matrix.md) 2절).

## 3. UI

상단 헤더 제목 "계정·직원 관리", 그 아래 탭 바. 탭 구성: **사무실 관리자(office) · 현장 관리자(field) · 입주자(tenant)** ([_status-codes.md](../../_status-codes.md) 9절 계정 유형). 좌·우 공통 LNB/RNB 공유(공통 인프라).

### 3.1 계정 목록 (사무실 관리자 / 현장 관리자 탭)
- **기능**: 선택 탭의 계정 목록 조회·선택, 신규 등록 진입.
- **규칙**:
  - 목록 컬럼: **이름 · 아이디 · 비밀번호 · 연락처 · 유형 · 상태**.
  - **유형**=회원 유형 마스터/일반, **상태**=활성/비활성 ([_status-codes.md](../../_status-codes.md) 9절). 상단에 계정 수 뱃지.
  - 행 클릭 시 등록·수정 모달 열림(기존 값 로드). 우상단 **「＋ 계정 등록」** 버튼.

### 3.2 계정 등록·수정 모달
- **기능**: 계정 생성·수정·삭제 및 권한 부여.
- **규칙**:
  - 계정 필드: **아이디\* · 비밀번호\*(숫자 4자리) · 이름\* · 연락처 · 회원 유형 · 상태** ([_data-dictionary.md](../../_data-dictionary.md) A2 계정 필드 준용). 비밀번호는 숫자 4자리.
  - **회원 유형**: 마스터/일반 ([_status-codes.md](../../_status-codes.md) 9절). **상태**: 활성/비활성. 수정 시 **삭제** 버튼 노출.
  - **탭별 차이**:
    - **사무실 관리자**: 회원 유형(마스터/일반) 선택 + **페이지별 권한 칩** 노출.
    - **현장 관리자**: **회원 유형·페이지별 권한 칩 미노출**(현장 관리자는 [_permission-matrix.md](../../_permission-matrix.md) 3절 고정 기능 세트를 따르므로 페이지 권한 설정 대상이 아님).

### 3.3 페이지별 권한 칩 (사무실 관리자)
- **기능**: 계정별로 LNB 항목 접근권한을 칩 on/off로 부여/제한. **이 화면이 staff 권한 부여의 정본**.
- **규칙**:
  - 칩 그룹([_permission-matrix.md](../../_permission-matrix.md) 2절 "관리업무 / 공과금 관리 / 이사정산 / 설정"):
    - **관리업무**: 건물·입주자 관리 · 관리비 부과 세팅 · 항목등록 관리 · 서류 발행·출력 · 미납 관리 · 협력업체 관리 · 장기수선비 관리 · 문자·알림톡 관리
    - **공과금 관리**: 공과금 관리 전체(고객번호·전기·수도·가스 묶음)
    - **이사정산**: 이사정산 전체(입력·조회 묶음)
    - **설정**: 계정·직원 · 셋업 설정
  - 부여된 LNB 항목만 해당 계정에 노출된다(권한 없는 메뉴 숨김, [_service-policy.md](../../_service-policy.md) 6절).
  - 마스터는 전체 접근(칩 설정과 무관하게 O). 권한 변경은 마스터만 가능.
  - 단, 현재 화면 칩 목록에는 **수납관리·민원접수 · 공지 관리가 빠져 있어 추가 보완 대상**이다(권한 칩은 [_permission-matrix.md](../../_permission-matrix.md) 2절 **전 LNB 14항목**이어야 함 — 사용자 확정).

### 3.4 입주자 탭 — 세대 연결
- **기능**: 카카오 입주자 계정과 세대 매핑 조회·수동 연결.
- **규칙**:
  - 필터 바: **건물 선택** 드롭다운 + 상태 세그(**전체 / 연결됨 / 미연결 / 매핑실패**) ([_status-codes.md](../../_status-codes.md) 9절 입주자 연결 상태).
  - 목록 컬럼: **건물명 · 호실 · 입주자명 · 연락처 · 카카오 ID · 카카오 이름 · 연결 상태 · 연결일** ([_data-dictionary.md](../../_data-dictionary.md) K절 res_claims).
  - **매핑실패** 행 클릭 → **세대 연결 모달**: 세입자가 입력한 건물·호실이 틀려도 올바른 세대를 검색해 수동 연결. 건물명·호실 검색 후 대상 선택 → **연결 확인 모달** → 연결.
  - resident `resident-verify`의 세대 확인 요청(res_claims)이 이 탭의 연결 처리로 이어진다([_screen-map.md](../../_screen-map.md) 롤 간 연동).

### 3.5 공통 RNB (A/S·퇴실 신청)
- **기능**: 우측 공통 패널로 A/S 접수·퇴실 신청 현황 표시(공통 인프라, 이 화면 고유 아님). 퇴실 신청 "처리 완료"는 확인 모달 후 반영.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 초기 | 화면 진입 | 사무실 관리자 탭·계정 목록 표시 |
| 빈/결과없음 | 탭·필터 결과 없음 | 안내 문구(공통 표준 [_service-policy.md](../../_service-policy.md) 6절) |
| 성공 | 등록·수정·연결 저장 | "저장되었습니다"/연결 완료 토스트, 목록 갱신 |
| 제한(권한) | 일반 계정이 권한 변경 시도 | 마스터만 가능, 변경 컨트롤 비활성 |
| 되돌릴 수 없는 액션 | 계정 삭제·퇴실 처리 완료 | 확인 모달 경유([_permission-matrix.md](../../_permission-matrix.md) 6절) |
| 에러 | 저장·연결 실패 | 실패 안내·재시도, 원본 훼손 없음([_service-policy.md](../../_service-policy.md) 6절) |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 계정(이름·아이디·PW·연락처·유형·상태) | 내부 DB — 계정 테이블(테넌트 격리) | 등록·수정 저장 시 |
| 페이지별 권한(LNB 항목) | 내부 DB — 권한 매핑 | 마스터 부여 시, 전 화면 LNB 노출에 반영 |
| 입주자 세대연결(res_claims) | resident `resident-verify` 요청 ([_data-dictionary.md](../../_data-dictionary.md) K) | 매핑실패 수동연결·상태 갱신 |
| 담당자 참조 | 건물 담당자(사무·현장·청소) 지정 | 이 화면 계정을 참조 |

- 발송(문자·알림톡) **자체 트리거 없음**(권한·계정 변경은 감사 로그에 자동 기록, [_service-policy.md](../../_service-policy.md) 8절).
