## 1. 목적

관리업체 직원이 **한 세대(호실)의 입주자 정보·부과 설정·공과금 고객번호·임대차·부동산 정보를 조회·수정**하고, 퇴실 처리·호수 삭제를 수행하는 화면.

## 2. 권한

| 사용자 | 접근 |
|---|---|
| staff (마스터) | O |
| staff (일반) | LNB "건물·입주자 관리" 권한 부여 시 O ([_permission-matrix.md](../../_permission-matrix.md) 2절) |

- partner는 세대 정보 **열람 전용**. 개인정보(연락처·계좌·차량·전출정보)는 보유·파기 정책 적용([_service-policy.md](../../_service-policy.md) 8절).

## 3. UI (섹션 순서)

### 3.0 상단 헤더
- **기능**: "{건물명} {호실}호" 제목 + 저장 / 목록으로.
- **규칙**: **저장**=전체 8섹션 통합 저장 → **저장 시 부과 모달(3.9)** 개입. **목록으로**=변경 시 이탈 확인 모달.

### 3.1~3.8 폼 8섹션 (등록과 동일)
동일 구조·필드 규칙은 [tenant-register.md](../tenant-register/tenant-register.md) 3절 참조. 요약:
1. **기본 정보** — 호실* · 입주자명 · 입금자명 · 룸 · 인원 · 평형 · 입주일 · 입주예정일 · 할인 유형(일반·수급자·다자녀·기타) · 할인 금액 · 기타적요 · 이사정산시 적요 + **퇴실 처리(3.10)**(섹션 끝).
2. **연락처·차량** — 전화번호(주/부, 다중) · 차량번호(다중) · 문자 수신(동의/거부) · 알림톡 수신(동의/거부) · 홈피 비밀번호. **알림톡·단체문자는 주번호·부번호 모두 수신**([_notification-policy.md](../../_notification-policy.md) 4절).
3. **관리비·부과** — 관리비 · 이사청소 · 인상액 · 부과금 여부(Y/N) · 부과일 · 이체 방식 · 효성 회원번호 · 계약번호 · 연체료 부과 여부(O/X) · 단수 출력 여부(O/X) · 부과시 참조사항.
4. **공과금 고객번호** — 수도/전기/공용전기/가스 고객번호·계량기 번호·한전고객번호·한전계기번호.
5. **고지서** — 출력 여부 · 이름 출력 유형 · 발송(우편 / 알림톡 고지서) · 인증. **알림톡 수신 동의 세대는 이체 방식과 무관하게 알림톡 고지서로 발송**된다.
6. **전출정보** — 퇴실 이력(이사일·이름·집전화·전화(주/부)·입주일), **읽기 전용** 표(퇴실 처리 시 자동 누적).
7. **임대 정보** — 임대구분·개시/만료일·보증금·보증금일(날짜 선택)·임대료·전세금·은행·계좌.
8. **부동산 정보** — 매물·시설정보 등.

### 3.9 저장 시 "이번달 부과?" 모달
- **기능**: 저장·등록 시, 해당 건물의 **당월분 부과가 이미 확정된 경우** 이 세대를 이번 달에 부과할지 물음.
- **규칙**:
  - 모달 문구: "이번달 관리비 부과를 하시겠습니까? / {연}년 {월}월분 부과가 이미 확정된 건물입니다. 부과하면 **입주일 기준 일할 계산**되어 반영됩니다."
  - 버튼: **[다음달부터]** → "다음달부터 부과됩니다" · **[이번 달 부과]** → "이번 달 관리비가 부과되었습니다".
  - 일할 계산은 [_calculation-rules.md](../../_calculation-rules.md) 1.1(분모 고정 30일)을 따른다. 중간 입주자 당월 부과 확인 취지(기능정의서 C-2).

### 3.10 퇴실 처리
- **기능**: 세대 퇴실 처리.
- **규칙**:
  - 방식 선택: **즉시 퇴실** / **퇴실 날짜 지정(예약)**.
  - 즉시 퇴실 → 완료 후 **전출정보(3.6)에 이력 누적**. 예약 → "퇴실 예정일" 예약 카드 표시, **예약 취소** 가능(자동 퇴실 해제).
  - 이사정산·공실 처리 분기는 [_calculation-rules.md](../../_calculation-rules.md) 6절(중도퇴실/정산완료+공실), 실제 정산은 `moving-settlement`. **정산은 자동으로 되지 않으므로**(즉시/예약 무관) 별도 이사정산이 필요하다.
  - **퇴실 완료 시 초기화(공실화)되는 입주자 귀속 값** — 아래 필드를 비워 공실 상태로 되돌린다. 이 중 이름·전화번호·입주일 등은 **전출정보(3.6)에 이력으로 남긴 뒤** 비운다.
    - **기본 정보**: 입주자명 · 입금자명 · 인원 · 입주일 · 입주예정일 · 할인 유형 · 할인 금액
    - **연락처·차량**: 전화번호 · 차량번호 · 문자 수신 · 알림톡 수신
    - **관리비·부과**: 이체 방식 · 연체료 부과 여부 · 단수 출력 여부
    - **고지서**: 출력 여부 · 이름 출력 유형 · 발송 · 인증
    - **임대 정보**: 임대구분 · 개시일 · 만료일 · 보증금 · 보증금일 · 임대료 · 전세금
  - **유지(초기화 안 함)**: 호실·룸·평형, **공과금 고객번호·계량기(수도·전기·공용전기·가스)**, 부과 그룹·관리비 설정 등 **호실 귀속 정보**와 **부과·수납 이력**(과거 데이터 보존, 3.11 호수 삭제와 동일 원칙). 미수금은 이사정산으로 정리.

### 3.11 호수 삭제
- **기능**: 세대(호수) 삭제(되돌릴 수 없음).
- **규칙**: 확인 모달 후 삭제, `building-list`로 이동. **부과·수납 이력이 있는 세대는 삭제 시 경고 후 진행**(완전 차단은 아님, 과거 데이터는 보존).

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 로딩 | 진입 조회 중 | 로딩 표시 |
| 조회/수정 | 로드 완료 | 값이 채워진 폼 |
| 검증 실패 | 호실 미입력 | 안내, 저장 차단 |
| 부과 확인 | 저장 시 당월 부과 확정 건물 | 이번달 부과 모달(3.9) |
| 성공 | 저장/퇴실/삭제 완료 | 토스트 |
| 이탈 확인 | 변경 후 목록 이동 | 확인 모달 |
| 에러 | 조회·저장 실패 | 실패 안내·재시도([_service-policy.md](../../_service-policy.md) 6절) |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 입주자·부과·고객번호·임대·부동산 | 내부 DB(테넌트 격리) | 진입 조회 / 저장 시 |
| 당월 부과 확정 여부 | 관리비 부과 세팅(`management-fee-setting`) | 저장 시 모달 판단 |
| 일할 부과 계산 | [_calculation-rules.md](../../_calculation-rules.md) 1.1 | 이번 달 부과 선택 시 |
| 전출정보 이력 | 입주 이력 데이터 | 퇴실 처리 시 자동 누적 |
| 퇴실·이사정산 | `moving-settlement` | 정산 흐름 |

- 발송 트리거 **없음**(연락처는 messaging·독촉 등 다른 화면에서 사용).
