## 테스트 케이스

### 로그인(카카오 시작)

#### TN-001 신규 사용자 카카오 로그인 → 온보딩 진입
- **화면/기능**: 로그인 / 카카오 시작
- **유형**: 정상
- **우선순위**: P1
- **사전조건**: 세대 매칭 이력이 없는 카카오 계정이 있다. `NEXT_PUBLIC_KAKAO_LOGIN_ENABLED=true` 환경이다.
- **절차**: 1. `resident-login`에 진입한다. 2. 히어로·프리뷰 카드·버튼을 확인한다. 3. 「카카오톡으로 3초 만에 시작」을 탭해 카카오 동의를 완료한다.
- **기대결과**: 히어로 "이번 달 관리비, 앱에서 바로 확인하세요"와 고정 프리뷰 카드(2026년 8월 관리비 · 납부 완료 · 128,400원 · 8월 21일 납부 · 그린빌라 201호)가 표시되고 로그인 수단은 카카오 단일 버튼뿐이다. 스텁이 아닌 실제 카카오 OAuth로 진입하고 공개 도메인 기준 콜백을 거쳐 본인인증·세대 연결 온보딩(`resident-auth`)으로 이동한다.
- **근거**: `policy/04_세입자/세입자_로그인카카오 시작.md` > 3.0 히어로, 3.1 프리뷰 카드, 3.2 카카오 시작 버튼

#### TN-002 세션 유효·매칭 완료 사용자 자동 로그인
- **화면/기능**: 로그인 / 자동 로그인
- **유형**: 상태전이
- **우선순위**: P1
- **사전조건**: 세대 매칭이 완료되고 세션이 유효한 세입자이다.
- **절차**: 1. 앱을 종료 후 다시 실행한다.
- **기대결과**: `resident-login` 화면을 건너뛰고 바로 홈(`resident-home`)으로 진입한다.
- **근거**: `policy/04_세입자/세입자_로그인카카오 시작.md` > 4. 화면 상태, 6. 결정됨

#### TN-003 카카오 인증 취소·실패
- **화면/기능**: 로그인 / 오류 처리
- **유형**: 예외
- **우선순위**: P1
- **사전조건**: 로그인 화면이다.
- **절차**: 1. 시작 버튼을 탭한다. 2. 카카오 동의 화면에서 취소하거나 인증을 실패시킨다.
- **기대결과**: 랜딩 화면이 유지되고 재시도 안내(공통 표준)가 표시되며 온보딩·홈으로 이동하지 않는다.
- **근거**: `policy/04_세입자/세입자_로그인카카오 시작.md` > 3.2 카카오 시작 버튼, 4. 화면 상태; `policy/01_공통 정책/서비스 전체 정책서 (4개 롤 통합).md` > 6. 공통 화면 상태
- **비고**: 구체 실패 문구는 공통 표준 준용으로만 정의됨(정책 미정).

#### TN-004 프로필 사진 선택 동의 거부 시 로그인 진행
- **화면/기능**: 로그인 / 카카오 동의 항목
- **유형**: 정상
- **우선순위**: P2
- **사전조건**: 매칭 가능한 카카오 계정이다.
- **절차**: 1. 카카오 동의에서 전화번호·이름·닉네임은 동의하고 프로필 사진(선택)은 동의하지 않는다. 2. 온보딩을 진행해 `resident-verify` 카드를 확인한다.
- **기대결과**: 로그인이 정상 진행되고, 매칭 세대 카드 아바타가 이름 첫 글자 아바타로 표시된다.
- **근거**: `policy/04_세입자/세입자_로그인카카오 시작.md` > 3.2 카카오 시작 버튼; `policy/04_세입자/세입자_매칭 세대 확인.md` > 3.1 매칭 세대 카드

#### TN-005 미인증·타 persona의 세입자 화면 접근 차단
- **화면/기능**: 세입자 페이지·API / 인가 게이트
- **유형**: 권한
- **우선순위**: P1
- **사전조건**: 비로그인 브라우저, staff·partner 계정이 있다.
- **절차**: 1. 비로그인 상태로 `resident-home`·`resident-bill` URL에 직접 접근한다. 2. staff·partner 계정 세션으로 동일 페이지와 세입자 API를 호출한다.
- **기대결과**: 관리비 등 실데이터가 노출되지 않는다. 타 persona는 페이지(`requirePersona`)·API(`requirePersonaApi`) 서버 게이트에서 차단된다.
- **근거**: `policy/04_세입자/세입자_로그인카카오 시작.md` > 2. 권한; `policy/01_공통 정책/권한 매트릭스 (Permission Matrix).md` > 4. resident, 7. 크로스-persona 인가 게이트 & 겸직
- **비고**: 비로그인 접근 시 리다이렉트 대상 화면은 명시되지 않음(정책 미정).

### 본인인증·세대 매칭

#### TN-006 3단계 자동 진행 후 매칭 성공
- **화면/기능**: 본인인증·세대 매칭 / 자동 매칭
- **유형**: 정상
- **우선순위**: P1
- **사전조건**: 카카오 계정 전화번호가 관리주체가 등록한 입주자 연락처와 일치한다.
- **절차**: 1. 카카오 인증 성공 직후 `resident-auth`를 관찰한다.
- **기대결과**: 입력 컨트롤 없이 점 3개 인디케이터와 함께 "카카오 계정으로 확인 중" → "세대 정보를 찾고 있어요" → "거의 다 됐어요"가 각 약 0.9초 간격으로 진행되고, 별도 PASS/SMS 인증 없이 `resident-verify`로 자동 이동한다.
- **근거**: `policy/04_세입자/세입자_본인인증·세대 매칭.md` > 3.0 진행 메시지 + 단계 표시, 3.1 완료 후 자동 분기

#### TN-007 등록 세대 없음 → 매칭 실패 분기
- **화면/기능**: 본인인증·세대 매칭 / 자동 분기
- **유형**: 상태전이
- **우선순위**: P1
- **사전조건**: 카카오 전화번호가 어떤 세대 입주자 연락처에도 등록되어 있지 않다.
- **절차**: 1. 카카오 로그인 후 `resident-auth` 진행을 기다린다.
- **기대결과**: 매칭 실패로 판정되어 `resident-nomatch`로 자동 이동한다.
- **근거**: `policy/04_세입자/세입자_본인인증·세대 매칭.md` > 3.1 완료 후 자동 분기, 4. 화면 상태

#### TN-008 세대 조회 서버 오류
- **화면/기능**: 본인인증·세대 매칭 / 오류 처리
- **유형**: 예외
- **우선순위**: P2
- **사전조건**: 세대 조회 API가 실패하도록 설정한다.
- **절차**: 1. 카카오 로그인 후 `resident-auth`에 진입한다.
- **기대결과**: 재시도 안내(공통 표준)가 표시되고, 매칭 실패(`resident-nomatch`)로 잘못 분기하지 않는다.
- **근거**: `policy/04_세입자/세입자_본인인증·세대 매칭.md` > 4. 화면 상태; `policy/01_공통 정책/서비스 전체 정책서 (4개 롤 통합).md` > 6. 공통 화면 상태
- **비고**: 오류 문구·재시도 UI 형태는 공통 표준 준용으로만 정의됨(정책 미정).

- **사전조건**: 입주자 이름 `박정호`, 전화 `010-1234-7788`로 매칭된 세대가 있다.
- **절차**: 1. `resident-verify`에 진입해 제목·카드·안내를 확인한다.

- **근거**: `policy/04_세입자/세입자_매칭 세대 확인.md` > 3.0 헤더/안내, 3.1 매칭 세대 카드

#### TN-011 "제 세대가 아니에요" → 직접 찾기 제출

- **유형**: 정상
- **우선순위**: P1
- **사전조건**: 관리 중인 건물 "그린빌라(봉명동)"가 있다.
- **절차**: 1. 「제 세대가 아니에요」를 탭한다. 2. 1단계에서 "봉명동"으로 검색해 그린빌라를 선택한다. 3. 2단계에서 호수 `201`을 입력해 제출한다.
- **기대결과**: 바텀시트 1단계 "어느 건물에 사시나요?"(placeholder "예: 그린빌라 · 봉명동")에서 동 이름·주소 일부로 관리 중인 건물이 검색된다. 제출 시 "관리사무소 확인 후 세대를 연결해 드려요"가 안내되고 `resident-pending`으로 이동한다.
- **근거**: `policy/04_세입자/세입자_매칭 세대 확인.md` > 3.3 세대 직접 찾기 바텀시트

### 세대 승인 대기

#### TN-015 승인 대기 화면 표시
- **화면/기능**: 세대 승인 대기 / 안내·요청 정보·문의
- **유형**: 정상
- **우선순위**: P1
- **사전조건**: 그린빌라 201호로 직접 연결 요청을 2026.08.07 15:53에 제출했다. 관리주체는 스마일종합관리(042-822-4410)이다.

#### TN-047 알림톡 토글 즉시 저장·수신 반영

- **유형**: 알림
- **우선순위**: P1
- **사전조건**: 알림톡 수신 ON 상태이다.
- **절차**: 1. 알림톡 토글을 OFF로 바꾼다. 2. 화면을 이탈 후 재진입한다. 3. staff가 관리비 확정 알림톡을 발송한다. 4. 토글을 다시 ON으로 바꾼다.
- **기대결과**: ON 문구 "관리비 확정 안내와 서비스 공지를 카카오톡으로 받아요", OFF 문구 "관리비가 확정돼도 알려드리지 않아요"가 표시된다. 별도 저장 버튼 없이 즉시 저장되어 재진입 시 OFF로 유지되고, OFF 동안 관리비 확정 알림톡을 받지 않는다. 온보딩(`resident-notify`) 설정과 동일 값이다.

- **우선순위**: P1

## 정책 미정·확인 필요 항목

- **공유 링크 유효기간 기준 충돌**: 고지서 정책·권한 매트릭스는 `고지월 + 12개월`(만료 시 금액 마스킹), 서비스 전체 정책 4.4는 `1년`, 알림 정책 6절은 `발송일 기준` 만료와 `?mode=guest` 경로를 기재한다. TN-041은 최신 화면 정책(2026-09-08)을 적용했으며 만료 기준 시각도 확정이 필요하다.
- **공지 공유 링크 유효기간**: 알림 정책은 공지 딥링크 "기간 만료"를 기재하지만 공지 상세 정책에는 유효기간이 없다(TN-045).
- **완납 뱃지 문구**: 홈은 `납부완료`, 관리비 내역·고지서는 `완납`으로 표기된다. 공통 상태·코드의 수납 상태는 `완납·부분(분할)`만 정의하고 `미납`은 없다(TN-024, TN-033).
- **월 평균·3개월 평균 반올림**: 원 미만 금액의 표시 규칙이 없다(TN-025, TN-032).
- **승인 대기 → 다음 화면**: 대기 화면 정책은 승인 시 자동으로 홈, 화면 지도는 `pending → notify`로 기재한다. 승인 통지 채널(카카오/푸시)과 감지 방식(폴링/푸시)도 미확정이다(TN-016).
- **대기 중 재로그인 경로**: 로그아웃 후 재로그인 시 `resident-auth` 재진행 여부와 대기 화면 복귀 경로가 정의되지 않았다(TN-018).
- **비정형 호수 처리**: `B101` 안내 후 제출 허용 여부가 불명확하다(TN-012).
- **퇴실 3일 여유 경계**: D+3 포함 여부와 `done`(정산 완료) 상태의 세입자 화면 표시가 정의되지 않았다(TN-029, TN-030).
- **건물 공지 배너 미입력 시**: 홈 정책은 "기본/비노출(운영 정책에 따름)", 데이터 사전은 "비우면 미표시"로 기재한다(TN-027).
- **공지 읽음 처리**: 미읽음 dot 해제 시점이 정의되지 않았다(TN-043). 공통 코드의 `important=앱 홈 상단 강조`는 홈 정책에 반영되어 있지 않다.
- **카카오/스마트 고지서 신청**: 권한 매트릭스·서비스 정책은 `resident-home/me`의 신청 기능을 기재하지만 세입자 화면 정책에는 별도 UI가 없고 알림톡 토글만 있다. 2026-08-11 회의록은 알림톡 수신 동의 시 카카오 고지서 전환 안내를 세입자 웹에 명시하기로 했으나 화면 정책에 해당 문구가 없다.
- **하단 탭 준비 중 메뉴**: "납부 이력" 등 프로토타입 "준비 중" 메뉴의 실제 제공 여부가 미정이다(TN-022).
- **개인정보 보유기간**: 서비스 정책 8절은 계약 종료 후 5년(잠정), 처리방침은 탈퇴 시 지체 없이 파기(법령 보존 예외)로 기재한다(TN-048).
- **오류·빈 상태 문구**: 로그인 실패·매칭 조회 실패·서명 검증 실패·복사 완료 등은 `공통 표준 준용`으로만 정의되어 기대결과에 구체 문구를 지정하지 않았다(TN-003, TN-008, TN-038, TN-040).
- **비로그인 접근 리다이렉트**: 미인증 사용자의 세입자 화면 직접 접근 시 이동 화면이 정의되지 않았다(TN-005).
