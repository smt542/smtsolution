## 테스트 케이스

### 로그인

#### FM-001 현장관리자 로그인 성공
- **화면/기능**: 로그인(`partner/mobile-login`) / 인증
- **유형**: 정상
- **우선순위**: P1
- **사전조건**: field(partner) capability를 가진 활성 현장관리자 계정이 있다.
- **절차**: 1. 아이디·비밀번호를 입력한다. 2. 로그인 버튼을 누른다.
- **기대결과**: "로그인 중이에요" 안내가 표시된 뒤 홈(`mobile-home`)으로 이동한다.
- **근거**: `policy/02_현장 관리자/현장 관리자_현장관리자 로그인.md` > 3.3 로그인 버튼 · 안내, 4. 화면 상태

#### FM-002 아이디·비밀번호 미입력 검증
- **화면/기능**: 로그인 / 입력 검증
- **유형**: 검증
- **우선순위**: P1
- **사전조건**: 로그인 화면에 진입했다.
- **절차**: 1. 아이디를 비우고 로그인한다. 2. 아이디만 입력하고 비밀번호를 비운 채 로그인한다.
- **기대결과**: 각 경우 해당 필드에 인라인 에러("아이디를 입력해 주세요" 등)가 표시되고 그 필드로 포커스가 이동하며 인증 요청이 진행되지 않는다.
- **근거**: `policy/02_현장 관리자/현장 관리자_현장관리자 로그인.md` > 3.3, 4. 화면 상태

#### FM-003 비밀번호 표시 토글·자동 로그인(아이디 유지)
- **화면/기능**: 로그인 / 비밀번호 토글·자동 로그인
- **유형**: 정상
- **우선순위**: P2
- **사전조건**: localStorage를 사용할 수 있다.
- **절차**: 1. 비밀번호 입력 후 eye 토글을 누른다. 2. 자동 로그인을 체크하고 로그인 후 재방문한다. 3. 자동 로그인을 해제하고 재방문한다.
- **기대결과**: 비밀번호는 기본 마스킹이며 토글 시 표시/숨김이 전환된다. 체크 시 아이디만 로컬에 저장되어 재방문 시 프리필되고, 해제 시 저장값이 삭제되어 프리필되지 않는다.
- **근거**: `policy/02_현장 관리자/현장 관리자_현장관리자 로그인.md` > 3.1, 3.2

#### FM-004 타 persona 계정 로그인·접근 차단 및 겸직 허용
- **화면/기능**: 로그인·페이지·API / 크로스-persona 인가 게이트
- **유형**: 권한
- **우선순위**: P1
- **사전조건**: staff(사무실 전용)·resident·HQ 계정, 사무실+현장 겸직 계정이 있다.
- **절차**: 1. 각 계정으로 `mobile-login`에 로그인한다. 2. 사무실 전용 계정으로 partner 페이지 URL과 API를 직접 호출한다.
- **기대결과**: staff·resident·HQ 계정은 서버 게이트(`requirePersona`/`requirePersonaApi`)로 로그인·페이지·API 접근이 차단된다. 겸직 계정은 현장 capability를 보유하므로 로그인되어 홈으로 이동한다.
- **근거**: `policy/02_현장 관리자/현장 관리자_현장관리자 로그인.md` > 2. 권한; `policy/01_공통 정책/권한 매트릭스 (Permission Matrix).md` > 7. 크로스-persona 인가 게이트 & 겸직

#### FM-005 인증 실패 및 화면 구성 제한
- **화면/기능**: 로그인 / 오류 처리
- **유형**: 예외
- **우선순위**: P1
- **사전조건**: 존재하지 않는 아이디 또는 틀린 비밀번호를 준비한다.
- **절차**: 1. 잘못된 자격 증명으로 로그인한다. 2. 화면의 링크·안내를 확인한다.
- **기대결과**: 실패 사유 안내와 재시도 수단이 표시되고 홈으로 이동하지 않는다. 회원가입·비밀번호 찾기·소셜 로그인 링크가 없고, 하단에 "계정 문의는 관리사무소(문의 042-632-8770)" 안내가 고정 표시된다.
- **근거**: `policy/02_현장 관리자/현장 관리자_현장관리자 로그인.md` > 1. 목적, 3.3, 4. 화면 상태; `policy/01_공통 정책/서비스 전체 정책서 (4개 롤 통합).md` > 6. 공통 화면 상태
- **비고**: 서버 실패 사유의 구체 문구는 정책에 정의되어 있지 않다(공통 표준 준용).

### 홈(A/S현황)

#### FM-006 담당 건물 전체 A/S 목록·'내 담당' 뱃지 표시
- **화면/기능**: 홈(`partner/mobile-home`) / A/S 목록 카드
- **유형**: 정상
- **우선순위**: P1
- **사전조건**: 로그인한 현장관리자의 담당 건물에 본인 담당 A/S와 타인 담당 A/S가 함께 있고, 비담당 건물에도 A/S가 있다.
- **절차**: 1. 로그인 후 홈에 진입한다. 2. 카드 목록을 확인한다.
- **기대결과**: 담당 건물의 A/S 전체가 표시되고 비담당 건물 A/S는 표시되지 않는다. 각 카드에 유형·상태 뱃지·건물/호실·접수내용(2줄)·접수일자·담당자가 표시되며, 본인 담당 건은 '내 담당' 뱃지, 타인 건은 담당자명이 표시된다.
- **근거**: `policy/02_현장 관리자/현장 관리자_모바일 홈AS현황.md` > 1. 목적, 2. 권한, 3.4 A/S 목록 카드
- **비고**: 공통 서비스 정책서 2.3은 "본인에게 할당된 A/S 현황 조회"로 기재되어 있으나, 화면 정책 2026-08-14 결정(담당 건물 전체 + 내 담당 표시)을 적용했다.

#### FM-007 텍스트 검색 대상 범위
- **화면/기능**: 홈 / 검색
- **유형**: 정상
- **우선순위**: P2
- **사전조건**: 목록에 서로 다른 건물명·호실·접수내용·유형의 A/S가 있다.
- **절차**: 1. 검색창에 건물명, 호실, 접수내용 일부, 유형명을 각각 입력한다.
- **기대결과**: placeholder는 "건물명·호실 검색"이며, 입력 즉시 건물명·호실·접수내용·유형 중 일치하는 카드만 남는다.
- **근거**: `policy/02_현장 관리자/현장 관리자_모바일 홈AS현황.md` > 3.1 검색

#### FM-008 상태 필터·정렬
- **화면/기능**: 홈 / 상태 필터 칩·정렬
- **유형**: 정상
- **우선순위**: P2
- **사전조건**: 미결·보류·완결·반복 상태 A/S가 접수일시가 서로 다르게 존재한다.
- **절차**: 1. 진입 직후 필터·정렬 기본값을 확인한다. 2. `미결` 칩을 선택한다. 3. 정렬 하단 시트에서 `오래된순`을 선택한다.
- **기대결과**: 기본값은 `전체`·`최신순`이다. 칩은 `전체·미결·보류·완결·반복` 중 단일 선택이며 `미결` 선택 시 미결 건만 남는다. `오래된순` 선택 시 접수일시 오름차순으로 정렬된다. 상태 뱃지 색상은 미결=red·보류=amber·완결=green·반복=violet이다.
- **근거**: `policy/02_현장 관리자/현장 관리자_모바일 홈AS현황.md` > 3.2, 3.3, 3.4; `policy/01_공통 정책/상태·코드 정의 (Status & Codes).md` > 1. 민원 · A/S

#### FM-010 카드·신규 접수 이동
- **화면/기능**: 홈 / 화면 이동
- **유형**: 정상
- **우선순위**: P2
- **사전조건**: 목록에 A/S가 1건 이상 있다.
- **절차**: 1. 상단 `＋ 신규 접수` 버튼을 누른다. 2. 홈으로 돌아와 카드 1건을 탭한다.
- **기대결과**: 신규 접수 버튼은 `mobile-as-new`로, 카드 탭은 해당 A/S를 전달하며 `mobile-as`(상세)로 이동한다. 화면 내 문자·알림톡 발송 기능은 없다.
- **근거**: `policy/02_현장 관리자/현장 관리자_모바일 홈AS현황.md` > 3.0, 3.4, 2. 권한

### A/S 신규 접수

#### FM-011 신규 A/S 접수 등록 성공
- **화면/기능**: 신규 접수(`partner/mobile-as-new`) / 등록
- **유형**: 정상
- **우선순위**: P1
- **사전조건**: 담당 건물이 1개 이상 있다.
- **절차**: 1. 건물·호수·유형을 선택하고 접수 내용을 입력한다. 2. `접수 등록` → 확인 모달에서 확인한다.
- **기대결과**: 완료 토스트 후 `mobile-home`으로 복귀하며, 신규 건이 목록 상단에 추가된다. 처리결과(상태)를 변경하지 않았으면 `미결`로 등록된다.
- **근거**: `policy/02_현장 관리자/현장 관리자_모바일 AS 신규 접수.md` > 3.3, 3.4

#### FM-012 접수 내용 미입력 시 등록 차단
- **화면/기능**: 신규 접수 / 입력 검증
- **유형**: 검증
- **우선순위**: P1
- **사전조건**: 신규 접수 화면이다.
- **절차**: 1. 접수 내용을 비운 채(공백만 포함 케이스 포함) `접수 등록`을 누른다.
- **기대결과**: 등록이 차단되고 "접수 내용을 입력해 주세요"가 표시되며 확인 모달은 열리지 않고 데이터가 생성되지 않는다.
- **근거**: `policy/02_현장 관리자/현장 관리자_모바일 AS 신규 접수.md` > 3.2, 4. 화면 상태
- **비고**: 공백만 입력한 경우의 처리(trim 여부)는 정책에 명시되어 있지 않다(정책 미정).

#### FM-013 접수자·담당자 본인 고정 및 접수일시 자동
- **화면/기능**: 신규 접수 / 접수 정보
- **유형**: 권한
- **우선순위**: P1
- **사전조건**: 현장관리자 A로 로그인했다.
- **절차**: 1. 신규 접수 화면의 접수자·담당자·접수일시 필드를 확인한다. 2. 등록 후 홈 카드를 확인한다.
- **기대결과**: 접수자·담당자는 로그인한 A 본인으로 고정된 읽기 전용이며 변경할 수 없다. 접수일시는 오늘로 자동 입력된다. 등록 건은 홈에서 '내 담당' 뱃지로 표시된다.
- **근거**: `policy/02_현장 관리자/현장 관리자_모바일 AS 신규 접수.md` > 2. 권한, 3.2

#### FM-014 건물 변경 시 호수 목록 재구성·기본값
- **화면/기능**: 신규 접수 / 대상 세대 선택
- **유형**: 상태전이
- **우선순위**: P2
- **사전조건**: 호실 구성이 다른 담당 건물 A·B가 있다.
- **절차**: 1. 건물 A·호수 101을 선택한다. 2. 건물을 B로 변경한다. 3. 건물 드롭다운 목록을 확인한다.
- **기대결과**: 건물 드롭다운에는 담당 건물만 노출된다. 건물 변경 시 호수 목록이 B의 호실로 재구성되고 호수 값은 `건물 전체`로 초기화된다. 호수 목록 첫 항목은 `건물 전체`이다.
- **근거**: `policy/02_현장 관리자/현장 관리자_모바일 AS 신규 접수.md` > 3.1 대상 세대

#### FM-015 취소 확인 모달 및 시간 보정
- **화면/기능**: 신규 접수 / 취소·시간 입력
- **유형**: 경계값
- **우선순위**: P2
- **사전조건**: 신규 접수 화면에 일부 값을 입력했다.
- **절차**: 1. 시간에 `24:60`, `23:59`, `00:00`을 각각 입력한다. 2. 시행일자 입력 방식을 확인한다. 3. `취소`를 누르고 확인한다.
- **기대결과**: 시간은 HH:MM 숫자 입력이며 00~23시·00~59분 범위로 보정되어 `23:59`, `00:00`은 그대로 허용된다. 시행일자는 달력으로만 선택한다. 취소 시 입력 내용 미저장 안내 확인 모달이 표시되고 확인하면 저장 없이 `mobile-home`으로 복귀한다.
- **근거**: `policy/02_현장 관리자/현장 관리자_모바일 AS 신규 접수.md` > 3.3, 3.4; `policy/01_공통 정책/서비스 전체 정책서 (4개 롤 통합).md` > 5. 공통 UI·인터랙션 규칙
- **비고**: 범위를 벗어난 값(`24:60`)의 구체 보정 결과(최댓값 클램프 등)는 정책에 명시되어 있지 않다(정책 미정).

### A/S 상세

#### FM-016 처리결과 기록·저장
- **화면/기능**: A/S 상세(`partner/mobile-as`) / 처리 저장
- **유형**: 상태전이
- **우선순위**: P1
- **사전조건**: 본인 담당 `미결` A/S가 있다.

- **기대결과**: 제목이 "이사정산 상세"이고 저장값이 프리필되며 취소 버튼이 빨간색 `삭제`로 바뀐다. 내역서는 정산 항목별 상세+합계와 회사명 워터마크를 포함한 PNG 파일 다운로드만 제공되고 문자·알림톡 발송 수단은 없다. 삭제는 확인 모달 후 목록에서 제거되며 복구할 수 없다.
- **근거**: `policy/02_현장 관리자/현장 관리자_이사정산 등록·상세.md` > 2. 권한, 3.9; `policy/01_공통 정책/출력물·서식 정의 (Output Forms).md` > 4
- **비고**: 공통 문서(권한 매트릭스 3절·알림 정책 3절·출력물 4절·화면 지도)는 `mobile-moving-settlement`의 정산내역서 문자 전송을 기재하지만, 화면 정책은 해당 간이 화면 삭제·발송 없음으로 확정했다. 화면 정책을 적용했다.

## 정책 미정·확인 필요 항목

- **A/S 조회 범위 충돌**: 서비스 전체 정책서 2.3은 "본인에게 할당된 A/S 현황 조회", 홈 화면 정책은 "담당 건물 전체 + 내 담당 뱃지"(2026-08-14 결정)다. 본 문서는 화면 정책을 적용했다(FM-006).
- **타인 담당 A/S 상세의 쓰기 권한**: 홈에서 타인 담당 건 상세 진입이 가능하지만, 상세 화면 정책은 "본인 A/S 수정·저장·삭제"만 정의한다. 타인 건을 읽기 전용으로 둘지, 버튼을 비활성할지 정해야 한다(FM-020).
- **간이 이사정산 화면·정산문자 발송 충돌**: 권한 매트릭스 3절, 알림·발송 정책 3절, 출력물 4절, 화면 지도는 `mobile-moving-settlement`와 "정산내역서 문자 전송"을 기재한다. 반면 화면 정책은 간이 화면 삭제와 partner 발송 없음(PNG 저장 전용)으로 확정했다. 공통 문서 정리가 필요하다(FM-048).
- **일할 분모 충돌**: 계산 규칙 1.1은 "분모 고정 30일", 이사정산 화면은 입력값 `계산일수 기준`을 분모로 사용한다. 기준일수가 30이 아닌 입력을 허용할지 확인해야 한다(FM-043).
- **미수금 산식 차이**: 계산 규칙 6절은 `정산요금 = ①관리비 + ②공과금 + ④청소·기타 + ③미납 − 당월수납액`, `미수금 = 정산요금 − 수납액`이다. 화면 정책은 `미수금 = ①공과금 + ②관리비 + ③기타 + ④청소 − 수납액`이다(미납 합산·당월수납액 항목 없음). 본 문서는 화면 정책을 적용했다(FM-044).
- **round 방식**: 공과금 금액·관리비 일할의 `round` 단위(원/10원)와 0.5 처리 방식이 화면 정책에 없다(FM-042).
- **급증 경고 N% 산출 기준**과 **신규 뱃지 60일 경계일 산정**이 정의되어 있지 않다(FM-036, FM-039).
- **시간 HH:MM 보정 방식**: 범위를 벗어난 입력의 보정 결과(클램프 등)가 정의되어 있지 않다(FM-015).
- **검증 문구 미정**: 이사정산 퇴실일자 미입력 안내, 각 화면 로딩·에러 실패 문구는 "공통 표준 준용"만 명시되어 있다. 정책에 없는 문구는 기대결과에 임의로 지정하지 않았다.
- **빈 상태 문구 차이**: 공통 표준은 "검색 결과가 없습니다", 화면 정책은 "검색 결과가 없어요"/"해당하는 접수 내역이 없어요"다. 화면 정책 문구를 적용했다.
- **공통 수납 구분 표기**: 상태·코드 3절은 partner 수납 구분을 "지로/일반"으로 표기하지만, 입주자 정보 화면은 구분 값 제한을 명시하지 않는다. 표시 범위를 확인해야 한다.
- **프로필 비밀번호 표시**: 조회 화면에서 비밀번호 원문을 표시/숨김 토글하도록 정의되어 있다. 원문 저장·전송 여부 등 보안 검토가 필요하다(FM-049).
