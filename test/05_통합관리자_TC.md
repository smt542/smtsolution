### 로그인

#### PA-001 platform_admin 로그인 성공
- **화면/기능**: 로그인 / 인증
- **유형**: 정상
- **우선순위**: P1
- **사전조건**: 활성 platform_admin 계정이 있다.
- **절차**: 1. `admin/login`에서 유효한 아이디·비밀번호를 입력한다. 2. 로그인한다.
- **기대결과**: 인증 후 `admin/overview`로 이동한다.
- **근거**: `policy/05_통합 관리자/통합관리자_로그인.md` > 4. 화면 상태

#### PA-002 로그인 필수값 누락
- **화면/기능**: 로그인 / 입력 검증
- **유형**: 검증
- **우선순위**: P1
- **사전조건**: 로그인 화면이다.
- **절차**: 1. 아이디 또는 비밀번호를 비운다. 2. 로그인한다.
- **기대결과**: 누락 필드에 인라인 에러가 표시되고 포커스가 이동하며 인증되지 않는다.
- **근거**: `policy/05_통합 관리자/통합관리자_로그인.md` > 4. 화면 상태

- **우선순위**: P2

#### PA-023 복구 불가 삭제
- **화면/기능**: 테넌트 관리 / 삭제
- **유형**: 예외
- **우선순위**: P1

## 정책 미정·확인 필요 항목

- **본사 역할별 권한 충돌**: 화면 정책은 계정 관리·포인트 충전·설정 수정을 `마스터·운영`으로 제한하지만 공통 권한 매트릭스 5절은 admin 전체 `O`와 역할 차이 미구현을 기재한다. 본 문서는 더 구체적이고 최신인 화면 정책을 적용했다.
- **본사 계정 역할 코드 충돌**: 계정 화면은 `마스터/운영/지원/영업` 4종, 공통 상태·코드는 `회계/기타`까지 정의한다. 회계·기타의 폼 제공 여부 확인이 필요하다.
- **포인트 풀 단위 충돌**: 포인트 화면 정책과 2026-08-11 회의록은 본사 단일 풀을, 서비스 전체·알림 정책은 테넌트별 포인트와 하드 스톱을 기술한다. PA-031·PA-034는 화면 정책을 적용했다.
- **로그인 감사 로그 충돌**: 로그인 화면 정책은 모든 로그인 기록, 서비스 전체 정책 8절은 단순 로그인을 기록 제외로 정의한다. 성공·실패 중 기록 범위를 확정해야 한다.
- **대리 접속·테넌트 상세 충돌**: 화면 정책은 `tenant-detail`과 대리 접속을 삭제했지만 공통 권한 매트릭스·화면 지도·서비스 정책에는 남아 있다. 본 문서는 화면 정책을 적용했다.
- **청구서 이메일 범위**: 화면 정책은 출력/PNG 생성 및 발송 트리거 없음으로 정의한다. 회의록의 수동 이메일 전송 설명은 있으나 자동 이메일 발송 여부는 정책 미정이다.
- **공통 에러 문구 미정**: 각 화면은 `공통 표준 준용`만 명시하고 실제 실패 문구는 정의하지 않는다. 정책에 없는 문구는 기대결과에 임의 지정하지 않았다.
