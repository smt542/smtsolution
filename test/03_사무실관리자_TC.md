## 테스트 케이스

### 로그인

#### OM-001 office 계정 로그인 성공
- **화면/기능**: 로그인(`staff/login`) / 인증
- **유형**: 정상
- **우선순위**: P1
- **사전조건**: office capability를 보유한 활성 staff 계정이 있다.
- **절차**: 1. 아이디·비밀번호를 입력한다. 2. Enter 또는 로그인 버튼으로 제출한다.
- **기대결과**: 진행 중 "로그인 중…"이 표시되고 버튼이 비활성화되어 중복 제출이 막힌다. 성공 시 "로그인되었습니다" 토스트 후 업무 화면(수납관리·민원접수)으로 이동하며, 부여된 LNB 항목만 노출된다.
- **근거**: `policy/03_사무실 관리자/사무실 관리자_로그인.md` > 3.4 로그인 버튼, 5. 데이터 & 연동

#### OM-002 필수값 누락·인증 실패 처리
- **화면/기능**: 로그인 / 입력 검증·실패
- **유형**: 검증
- **우선순위**: P1
- **사전조건**: 로그인 화면이다.
- **절차**: 1. 아이디를 비우고 로그인한다. 2. 아이디만 입력하고 비밀번호를 비운 채 로그인한다. 3. 잘못된 비밀번호로 여러 번 로그인한다.
- **기대결과**: 1에서 "아이디를 입력해 주세요", 2에서 "비밀번호를 입력해 주세요" 오류가 표시되고 해당 필드로 포커스가 이동한다. 3에서 폼 상단 오류 영역에 사유가 표시되고 원본 입력이 유지되며, 실패 횟수와 무관하게 계정 잠금 없이 재시도할 수 있다.
- **근거**: `policy/03_사무실 관리자/사무실 관리자_로그인.md` > 3.1 아이디, 3.2 비밀번호, 3.4 로그인 버튼, 6. 결정됨(2026-08-12)

### 건물·입주자 관리

#### OM-003 건물 미선택 상태와 건물 목록 엑셀 다운로드
- **화면/기능**: 건물·입주자 관리(`/staff/buildings`) / 목록·엑셀
- **유형**: 정상
- **우선순위**: P2
- **사전조건**: 건물이 2개 이상 등록돼 있다.
- **절차**: 1. 화면에 진입해 하단 입주민 영역을 확인한다. 2. 건물명으로 검색 후 `⤓ 엑셀 다운`을 누른다. 3. 건물 행을 클릭한다.
- **기대결과**: 1에서 `건물을 선택해 주세요` 안내가 표시되고 입주민 엑셀·등록 액션이 비활성이다. 2에서 현재 검색 조건이 적용된 목록이 `건물목록_YYYYMMDD.xlsx`로 다운로드된다. 3에서 행이 강조되고 `{건물명} 호수·입주민`과 인원 배지, 세대 표가 표시되며 공실 세대는 `공실`로 표시된다.
- **근거**: `policy/03_사무실 관리자/사무실 관리자_건물·입주자 관리.md` > 3.2 건물 목록(마스터) 카드, 3.3 호수·입주민 목록 및 관리카드 모달

#### OM-004 출력 모달 부과내역서 P5 게이팅
- **화면/기능**: 건물·입주자 관리 / 입주자카드 및 부과내역 출력 모달
- **유형**: 상태전이
- **우선순위**: P1
- **사전조건**: 건물 A는 2026년 8월분 부과 확정, 9월분 미확정이다. 건물 A의 세대는 15세대다.
- **절차**: 1. `입주자카드 및 부과내역 출력`을 열고 건물 A를 선택한다. 2. 연·월을 2026년 9월로 선택한다. 3. 2026년 8월로 변경한다.
- **기대결과**: 2에서 부과내역서 대신 `확정된 부과 내역이 없습니다 / 관리비 부과 확정(P5) 후 표시됩니다` 안내가 표시되고 `내역서만 인쇄`가 비활성이다. 3에서 세대×항목 표가 14세대/쪽으로 분할되어 총 2장이 되고 마지막 쪽에 항목별·총 합계 행이 표시된다. 입주자카드는 세대 1장당 1장(총 15장)이며 두 문서 모두 회사명 워터마크가 표시된다.
- **근거**: `policy/03_사무실 관리자/사무실 관리자_건물·입주자 관리.md` > 3.4 입주자카드 및 부과내역 출력 모달

### 건물 등록

#### OM-005 필수값·날짜 선후 검증
- **화면/기능**: 건물 등록(`/staff/buildings/new`) / 저장 검증
- **유형**: 검증
- **우선순위**: P1
- **사전조건**: 건물 관리 모듈 권한이 있는 계정이다.
- **절차**: 1. 주소·사무 담당자·현장 관리자를 비운 채 저장한다. 2. 필수값을 채우고 계약일 2026-09-01, 해지일 2026-08-01로 저장한다. 3. 해지일을 계약일 이후로 고쳐 저장한다.
- **기대결과**: 1·2에서 저장되지 않고 문제 필드 근처에 원인이 표시되며 첫 오류로 이동할 수 있다(필수: 건물 코드·주소·사무 담당자·현장 관리자, 날짜 선후관계). 3에서 저장 중 중복 저장이 막히고, 성공 피드백 후 정해진 후속 화면으로 이동한다. 건물 코드 생성 방식(자동 채번 후 수정 vs 3자리 직접 입력)은 (정책 미정).
- **근거**: `policy/03_사무실 관리자/사무실 관리자_건물 등록.md` > 3.3 기본 정보, 4.1 기본 상태, 4.2 필수 검증, 7. 미결정 사항
- **비고**: 건물 코드 채번 방식은 미결정 1번.

#### OM-006 고객번호 카드·메모·보유 수 경계
- **화면/기능**: 건물 등록 / 부가 정보·건물 메모·기본 정보
- **유형**: 경계값
- **우선순위**: P2
- **사전조건**: 건물 등록 화면이다.
- **절차**: 1. 수도 유형 카드가 1개일 때 삭제를 시도한다. 2. `고객번호 추가`로 2개로 만든 뒤 두 번째 카드를 삭제한다. 3. 건물 메모에 1,000자 입력 후 1자를 더 입력한다. 4. 수도 고객번호 보유 수 선택지를 연다.
- **기대결과**: 1에서 삭제할 수 없다. 2에서 확인창 없이 즉시 제거되고 남은 카드의 입력값·순서는 유지된다. 3에서 1,001번째 글자는 입력되지 않고 현재 글자 수가 표시된다. 4에서 선택지는 1, 2, 3, 4, 5, 6, 7, 8, 10이며 9는 없다.
- **근거**: `policy/03_사무실 관리자/사무실 관리자_건물 등록.md` > 3.3 기본 정보, 3.7 부가 정보, 3.8 건물 메모

#### OM-009 당월 확정 건물 신규 세대 일할 부과
- **화면/기능**: 입주민 등록 / 저장 시 "이번달 부과?" 모달
- **유형**: 계산
- **우선순위**: P1
- **사전조건**: 2026년 9월분 부과가 확정된 건물이다. 일자계산 `적용` 항목의 월 기준금액은 60,000원이고, 신규 세대의 9월 실거주 일수는 10일이다.
- **절차**: 1. 신규 세대를 입력하고 등록 저장한다. 2. 모달에서 [이번 달 부과]를 누른다. 3. 다른 세대로 반복하며 [다음달부터]를 누른다.
- **기대결과**: 1에서 "이번달 관리비 부과를 하시겠습니까? / 2026년 9월분 부과가 이미 확정된 건물입니다. 부과하면 입주일 기준 일할 계산되어 반영됩니다." 모달이 표시된다. 2에서 "이번 달 관리비가 부과되었습니다"가 표시되고 해당 항목은 60,000 × (10 ÷ 30) = 20,000원으로 반영된다(분모 고정 30일). 3에서 "다음달부터 부과됩니다"가 표시되고 9월분은 부과되지 않는다.
- **근거**: `policy/03_사무실 관리자/사무실 관리자_입주민 등록.md` > 3.9; `policy/03_사무실 관리자/사무실 관리자_입주자 상세.md` > 3.9; `policy/01_공통 정책/부과·정산 계산 규칙 (Calculation Rules).md` > 1.1 일자 계산

#### OM-010 즉시 퇴실 시 공실화와 유지 항목
- **화면/기능**: 입주자 상세(`staff/tenant-detail`) / 퇴실 처리
- **유형**: 상태전이

- **기대결과**: 확인 모달 후 퇴실이 완료되고 전출정보(이사일·이름·집전화·전화(주/부)·입주일)에 이력이 누적된다. 초기화 25개 값(기본정보 7·연락처차량 4·관리비부과 3·고지서 4·임대정보 7)이 비워진다. 호실·룸·평형, 공과금 고객번호·계량기, 부과 그룹·관리비 설정, 부과·수납 이력은 유지된다. 이사정산은 자동 생성되지 않는다.
- **근거**: `policy/03_사무실 관리자/사무실 관리자_입주자 상세.md` > 3.10 퇴실 처리, 6. 결정됨(2026-08-14); `policy/01_공통 정책/권한 매트릭스 (Permission Matrix).md` > 6. 공통 권한 UI 규칙

#### OM-012 수도·공용전기 전환과 조회 전용 목록

- **입주민 등록 필수값 충돌**: 사무실 관리자 입주민 등록 정책은 `호실·전화번호`, `입주자 상세·등록 정책서 (UI중심)`은 `호실·입주자명·입금자명·룸·입주일`(+전화 첫 번째)을 필수로 정의한다. 입주자 상세 정책 4절은 검증 실패 조건을 `호실 미입력`만 적는다. OM-008은 최신 사무실 관리자 정책(2026-08-14 결정)을 적용했다.

- **A/S 확인문자 채널·템플릿 충돌**: 수납 화면 정책은 `민원·AS 처리 안내` 프리셋에 알림톡/SMS 자동 전환, 공통 알림 정책은 SMS 템플릿 3종(접수 확인/방문 예정/처리 완료)이다(OM-028).
- **임대 만료 알림 기준**: 수납 진입 모달은 30일 이내 고정, 셋업 알림 설정은 만료 N일 전(1·3·5·7·14·30) 선택이다. 두 설정의 연동 여부 확인이 필요하다(OM-029).
- **권한 판정 체계 혼재**: 권한 매트릭스는 LNB 14항목 칩 기준이지만, 화면별로 `billing`·`payment`/`complaints`/`messaging`·`overdue`·`utilities`·`bill_publish`·`tenants`·`moving` 모듈 키로 판정한다. 칩과 모듈 키의 매핑표가 필요하며, 계정·직원 칩에 수납관리·민원접수·공지 관리가 빠져 있다(보완 대상).
- **코드값 불일치**: 고지서 발송은 상태·코드 4절 `문자·우편` vs 화면 `우편/알림톡 고지서`. 연체료·단수 출력은 상태·코드 `O/X` vs UI 정책서 `Y/N`. 이체 방식 라벨도 `이체·입금` vs `계좌이체·무통장입금`으로 다르다.
- **연체 요율 적용 단위**: 셋업 설정은 테넌트 전역 화면에서 입력하지만 요율을 "건물 정책값", 계산 규칙은 "건물별 설정"으로 표현한다.
- **4사5입 단위**: 계산 규칙 1.2는 "일반 반올림"(단위는 화면 PRD 위임), 항목등록 관리는 10원 단위로 확정했다(OM-022).
- **이사정산 상태 `정산완료`**: 상태·코드에는 있지만 화면에는 이 상태로 남기는 액션이 없다(완료 경로는 중도퇴실·퇴실완료 둘뿐).
- **건물 등록 ❓**: 건물 코드 채번 방식, 계약서 사진 확장자·용량·보관기간, 주소 검색 공급자·직접 입력 허용, 동일 유형 고객번호 중복 차단 여부.
- **관리비 부과 세팅 ❓**: 공용전기 독립 데이터 분리, `전체자료추가` 일부 건물 실패 시 전체 롤백(OM-019).
- **공과금 ❓**: 전기·수도·가스 `전체 이월`의 모든 건물 서버 일괄 처리 API·실패 복구(현재 선택 건물 로컬 처리), 고객번호 요약 직접 수정 저장, 전기 검면·이사 원천, 집계행 클릭 필터, 퇴실일·전화·인원 등 API 매핑, 통합 검침대장 `전량·평균·미납액` 필드.
- **미납 관리 ❓**: `납.후연체` 원천·산식(0 표시, OM-031), 임시 CSV 출력의 A4 미납관리 현황 전환.
- **서류 발행·출력 ❓**: 자동이체 출력의 부과 그룹 1~5 매핑, 팩스 발신번호 목록 API(OM-025).
- **수납관리 ❓**: 지로 원장 수수료·실입금액·고객번호·코드, 처리일 달력 지표의 원천 필드(현재 일부 placeholder).
- **공통 에러 문구**: 대부분 화면이 `실패 안내·재시도`만 정의하므로 실패 문구는 기대결과에 임의 지정하지 않았다.
