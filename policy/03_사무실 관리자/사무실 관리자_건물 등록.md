## 2. 목적과 권한

### 2.1 목적

관리 사무실이 신규 관리 건물의 기본 정보, 담당자와 계약 업체, 적립금, 건물주, 공과금 고객번호 및 메모를 한 화면에서 등록한다.

### 2.2 접근 권한

- 사무실 마스터 또는 일반 사무실 계정 중 건물 관리 모듈 권한이 있는 사용자만 접근할 수 있다.
- 권한 확인 중에는 입력 화면을 노출하지 않는다.
- 권한이 없으면 기존 권한 제한 정책을 따른다.

## 3. 화면 구성과 정책

### 3.1 상단 헤더와 주요 액션

- 헤더는 메뉴 아이콘, 화면 제목, 뒤로가기, 저장 액션으로 구성한다.
- 최신 디자인에서는 주요 액션을 상단에 한 번만 제공하며 하단에 중복 배치하지 않는다.
- 뒤로가기 시 수정된 값이 있으면 이탈 확인을 노출한 뒤 이동한다.
- 저장 시 필수값과 형식을 검증하고, 성공하면 건물 목록 또는 등록 완료 화면으로 이동한다.
- /staff/buildings/new가 v2 등록 폼을 그대로 렌더링하며 저장 시 서버에 영속화한다. /new-v2는 같은 폼의 미리보기 라우트로 남아 있다.

### 3.2 공통 섹션 동작

- 화면은 다음 6개 번호형 섹션으로 구성한다.
  1. 기본 정보
  2. 업체 및 담당자 지정
  3. 적립금
  4. 건물주 정보
  5. 부가 정보
  6. 건물 메모
- 각 섹션은 접고 펼칠 수 있다.
- 섹션 또는 하위 아코디언을 닫아도 사용자가 입력한 값은 유지되어야 한다.
- 업체 유형과 공과금 유형은 각 섹션 안의 하위 아코디언으로 제공한다.
- 키보드와 보조기기 사용자가 현재 펼침 상태를 인지할 수 있어야 한다.

### 3.3 기본 정보

- 필드: 건물 코드, 건물명, 건물 유형, 공동현관 비밀번호, 주소와 상세주소, 고지서 부과 그룹 유형, 수도 고객번호 보유 수, 계약일, 해지일, 건물 상시 공지문.
- 필수값: 건물 코드, 주소.
- 건물 코드는 기존 확정 정책상 순차 자동 채번 후 수정 가능하다.
- 최신 Figma는 숫자 3자리 직접 입력 형태로 보이므로 운영 구현 전 최종 동작을 재확인한다.
- 수도 고객번호 보유 수 선택값은 1, 2, 3, 4, 5, 6, 7, 8, 10이다. 9는 제공하지 않는다.
- 건물 상시 공지문은 입주민 홈에 상시 노출한다.
- 계약일보다 해지일이 빠른 경우 저장할 수 없다.
- 주소 검색 결과 선택 후 상세주소를 입력할 수 있다.

### 3.4 업체 및 담당자 지정

- 사무 담당자와 현장 관리자는 필수 선택값이다.
- 업체 영역은 9개 유형별 하위 아코디언으로 구성한다.
- 업체는 업체 관리 마스터에서 선택한다.
- 업체 선택 시 업체 전화번호와 계좌 정보 등 마스터 보유값을 자동 반영하고, 자동 반영 필드는 읽기 전용으로 표시한다.
- 유형별 계약 정보 입력을 지원한다.
- 계약서 사진은 업체별 최대 10장까지 첨부할 수 있다.
- 업체별 비고를 입력할 수 있다.
- 담당자 선택지는 실제 직원 목록을 쓴다. 업체명 선택지는 아직 샘플 값(○○업체 등)이며 협력업체 마스터 연동이 남아 있다.

### 3.5 적립금

- 유형 선택값은 적립금, 장기수선충당금, 기타, 없음이다.
- 적립금 관련 메모를 입력할 수 있다.

### 3.6 건물주 정보

- 필드: 건물주명, 주 전화번호, 부 전화번호, 건물주 주소와 상세주소, 비고.
- 전화번호는 휴대전화와 지역번호 형식을 허용한다.
- 건물주 주소는 건물 주소와 별도로 검색하고 저장한다.

### 3.7 부가 정보

- 유형: 수도, 전기, 공동전기, 가스.
- 각 유형은 독립된 하위 아코디언으로 접고 펼칠 수 있다.
- 유형별로 최소 1개 카드를 유지한다. 카드가 1개일 때는 삭제할 수 없고, 2개 이상이면 확인창 없이 바로 제거되며 저장 시 서버에서 soft delete한다.
- 고객번호 추가 액션으로 같은 유형의 카드를 추가할 수 있다.
- 추가 카드 삭제 시 다른 카드의 입력값이나 순서를 훼손하지 않는다.
- 섹션 또는 아코디언을 닫아도 카드 수와 입력값을 유지한다.
- 공통 선택 정책:
  - 고지기간: 당월, 전월, 전전월
  - 계산법: 기본, 인원, 시조례, 시+톤당, 시+인원, 기타
- 수도, 전기, 공동전기, 가스 유형별로 Figma에 정의된 월분, 계산, 이체, 검침일, 고지기간, 출력 관련 필드를 제공한다.
- 공동전기는 전기보다 축약된 입력 구성을 사용한다.
- 가스는 다른 공과금과 구분되는 추가 입력 구성을 따른다.
- 부과시 참조사항은 관리비 부과 설정 화면에서 확인할 수 있도록 저장한다.

### 3.8 건물 메모

- 건물 전체에 대한 내부 메모를 입력한다.
- 최대 1,000자이며 현재 입력 글자 수를 표시한다.
- 제한을 넘는 입력은 허용하지 않는다.

## 4. 화면 상태와 피드백

### 4.1 기본 상태

- 권한 확인 중: 입력 화면을 표시하지 않는다.
- 입력 가능: 모든 허용 필드를 수정할 수 있다.
- 저장 중: 중복 저장을 막고 진행 상태를 표시한다.
- 검증 실패: 문제가 있는 필드 근처에 원인을 표시하고 첫 오류로 이동할 수 있게 한다.
- 저장 성공: 성공 피드백 후 정해진 후속 화면으로 이동한다.
- 저장 실패: 입력값을 유지한 채 재시도 가능한 오류를 표시한다.

### 4.2 필수 검증

- 건물 코드
- 주소
- 사무 담당자
- 현장 관리자
- 날짜 선후관계
- 첨부 개수와 파일 정책
- 동일 유형 내 고객번호 중복 여부는 운영 저장 정책과 함께 확정한다.

## 5. 데이터와 연동

- 운영 저장 대상은 건물, 주소, 담당자 배정, 업체 계약, 적립금, 건물주, 공과금 고객번호, 건물 메모 데이터다.
- 담당자는 사무실 계정 또는 담당자 마스터와 연동한다.
- 업체는 업체 관리 마스터와 연동한다.
- 계약서 사진은 업로드 저장소와 파일 메타데이터 저장이 필요하다.
- 주소는 주소 검색 공급자와 연동한다.
- 건물 상시 공지문은 입주민 홈 노출 데이터와 연결한다.
- 등록 폼은 저장 시 서버에 영속화한다(저장 RPC, 마이그 0124).

## 6. 접근성과 사용성

- 모든 입력은 연결된 레이블을 제공한다.
- 필수 여부를 색상만으로 구분하지 않는다.
- 아코디언 버튼은 펼침 상태를 보조기기에 전달한다.
- 아이콘 단독 버튼은 용도를 설명하는 접근성 이름을 제공한다.
- 오류, 저장 성공, 삭제 결과는 시각 피드백과 함께 인지 가능한 방식으로 알린다.
- 첨부 사진은 개별 삭제가 가능하고 삭제 대상을 구분할 수 있어야 한다.

## 7. 미결정 사항

1. 건물 코드를 기존 정책대로 자동 채번 후 수정 가능하게 할지, 최신 Figma처럼 숫자 3자리 직접 입력으로 확정할지 결정이 필요하다.
2. 계약서 사진의 허용 확장자, 장당 용량, 전체 용량, 저장 기간을 확정해야 한다.
3. 주소 검색 공급자와 주소 미검색 시 직접 입력 허용 여부를 확정해야 한다.
4. 동일 공과금 유형 내 고객번호 중복 차단 여부를 확정해야 한다.
