## 1. 목적

건물의 **수도·공용전기 고객번호를 한눈에 조회**하는 읽기 전용 화면이다. 고객번호·빌라명·주소·구분·기타적요를 기준으로 검색해 어느 건물의 고객번호가 어떤 설정인지 빠르게 확인한다. 고객번호의 등록·수정은 건물 상세의 부가정보에서 수행한다.

## 2. 권한

| 사용자 | 접근 |
|---|---|
| staff (마스터) | O (조회) |
| staff (일반) | 공과금 관리(utilities) 권한 보유 시 O |

- 화면과 조회 API 모두 현재 조직과 공과금 관리 권한을 기준으로 접근을 제한한다.
- **조회 전용**: 화면 안에 등록·수정·삭제·발행·수납 액션은 없다.

---

## 3. UI 및 동작

### 3.0 LNB 공과금 메뉴

- /staff/customer-numbers 진입 시 좌측 **공과금 관리** 아코디언을 펼친 상태로 유지한다.
- 하위 메뉴 중 **고객번호 조회**만 활성 표시한다.
- 고객번호 조회 화면에서는 전기·수도·가스 하위 메뉴를 동시에 활성 표시하지 않는다.
- 공과금 관리 권한이 없는 일반 staff에게는 메뉴와 화면을 노출하지 않는다.

### 3.1 유형 세그먼트

- 세그먼트는 **수도 / 공용전기** 두 항목으로 고정한다.
- 최초 진입 시 수도가 선택된다.
- 선택 유형에 따라 고객번호 열 제목을 **수도고객번호 / 공용전기고객번호**로 변경하고 해당 유형의 행만 조회한다.
- 유형을 변경하면 1페이지부터 다시 조회하며 이전 유형의 행을 잔류 표시하지 않는다.

### 3.2 결과 건수·통합검색·엑셀

- 현재 조건의 전체 결과 건수를 **조회 결과 N건**으로 표시한다.
- 검색 대상은 **고객번호·빌라명·주소·구분·계산 방식·LIN·기타적요**이며, 입력 후 300ms 뒤 서버 조회한다.
- 검색어가 바뀌면 1페이지부터 다시 조회한다.
- **엑셀 다운로드**는 현재 선택 유형과 검색어를 그대로 적용하며, 화면 표와 동일한 순서·한글 표시값으로 최대 10,000건을 내려받는다.

### 3.3 고객번호 목록

- 컬럼 순서: **코드 · 빌라명 · 주소 · LIN · {수도/공용전기}고객번호 · 일금일 · 구분 · 계산 · 기타적요**.
- 긴 빌라명·주소·고객번호·기타적요는 한 줄로 말줄임하고 원문은 툴팁으로 확인한다.
- **LIN**: 건물 상세에서 입력한 라인 값. 값이 없으면 -로 표시한다.
- **일금일**: 1~28. 값이 없으면 -로 표시한다.
- **구분**: 당월 / 전월.
- **계산**: 수도는 자동 / 수동, 공용전기는 자동으로 고정한다.
- **기타적요**: 자유 텍스트. 값이 없으면 -로 표시한다.
- 행 클릭과 상세 이동은 제공하지 않는다.
- 한 페이지에 50건을 표시하고 결과가 있을 때 이전/다음 페이지 이동을 제공한다.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 로딩 | 최초 조회 또는 조건 변경 후 조회 중 | 로딩 스피너 |
| 성공 | 고객번호 있음 | 목록과 페이지네이션 표시 |
| 결과 없음 | 선택 유형 또는 검색 결과 0건 | "검색 결과가 없습니다" |
| 에러 | 조회 실패 | 실패 안내와 "다시 시도" 버튼 |
| 권한 없음 | 로그인 정보 없음 또는 utilities 권한 없음 | "고객번호 조회 권한이 없습니다" |

## 5. 데이터 및 연동

| 항목 | 출처 / 연동 | 규칙 |
|---|---|---|
| 코드·빌라명·주소 | buildings | 현재 조직의 삭제되지 않은 건물 |
| 건물 고객번호 설정 | building_customer_numbers | 삭제되지 않은 수도·공용전기 행만 조회 |
| 세대 계량기 고객번호 | unit_meters.customer_no | 이 화면의 조회 대상이 아님 |
| LIN | building_customer_numbers.line_name | 선택 입력 |
| 계산 | building_customer_numbers.calculation_method | auto / manual, 공용전기는 auto 강제 |
| 기타적요 | building_customer_numbers.note | 선택 입력, UTF-8 한글 보존 |
| 엑셀 | /api/customer-numbers/export | 화면과 동일한 조회 RPC 및 조건 사용 |

- 조회는 조직 범위 서버 RPC에서 검색·정렬·페이지네이션을 처리한다.
- 정렬 순서는 건물 코드 → 건물 ID → 고객번호 정렬 순서 → 행 ID다.
- 건물 상세 저장 시 LIN·계산·기타적요를 고객번호 원장에 함께 저장한다.
- 세대별 수도·전기·가스 고객번호를 건물별 수도·공용전기 고객번호로 임의 변환하지 않는다.
- Supabase migration 0118이 원격 DB에 적용돼 신규 필드·조회 RPC·저장 RPC·권한 검사가 활성화돼 있다.
- 발송 트리거는 없다.

### 5.1 개발 확인 데이터

- 2026-08-31 개발 환경의 활성 건물 4개에 수도 2건·공용전기 2건씩 생성했다.
- 총 건수는 수도 8건, 공용전기 8건이며 로그인 권한 컨텍스트의 조회 RPC 반환까지 확인했다.
- 기타적요는 **[테스트]** 접두어로 실제 데이터와 구분한다.
- 위 16건은 화면 확인용 데이터이며 운영 데이터 생성 정책이 아니다. 실제 고객번호 입력 후 제거할 수 있다.

## 6. 검증 기준

- /staff/customer-numbers에서 공과금 관리 아코디언과 고객번호 조회 활성 표시가 유지된다.
- 수도/공용전기 전환, 동적 고객번호 열, 검색 조건, 결과 건수, 빈/로딩/에러 상태가 정책과 일치한다.
- 유형 전환 시 이전 유형 데이터나 다른 공과금 하위 메뉴의 선택 상태가 남지 않는다.
- 행은 클릭하거나 키보드로 상세 화면에 이동하지 않는다.
- 화면과 엑셀의 열 순서 및 한글 변환값이 일치한다.
- 일반 staff는 utilities 권한이 있을 때만 메뉴·화면·조회 데이터에 접근한다.
- 일금일은 신규 입력 시 1~28만 허용하고 공용전기의 계산 방식은 자동으로 저장한다.
- 테스트 데이터의 기타적요·명의자 한글은 UTF-8로 저장·표시한다.
