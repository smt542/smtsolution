## 1. 목적

관리업체 직원이 건물과 호실을 기준으로 월별 수납 이력, 입주자 정보, A/S 접수·처리 현황을 한 화면에서 조회하고 관리한다. 통합조회, 부과·미납·수납 출력, 호실 명세서·영수증, 지로·은행 자동수납까지 같은 작업 맥락에서 진입한다.

---

## 2. 권한

| 조건 | 접근/동작 |
|---|---|
| `payment` 또는 `complaints` 모듈 보유 | 화면 접근 가능 |
| `payment` 모듈 보유 | 수납 추가·수정·취소, 입주자/건물 참고사항 수정, 빌라·호실·자동수납 액션 노출 |
| `messaging` 모듈 보유 | 미납 안내 및 A/S 확인문자 발송 가능 |
| 두 접근 모듈 모두 미보유 | "수납관리·민원접수 권한이 없습니다" 안내 |

`payment`만 보유한 계정도 A/S 접수 추가·수정·삭제를 할 수 있다(`complaints` 모듈로 별도 제한하지 않음, 2026-09-23 확정).

## 3. UI

### 3.0 셸·상단 액션

- **기능**: 화면 식별 및 조회·출력·자동수납 기능 진입.
- **규칙**:
  - 데스크톱 기준 좌측 240px LNB, 상단 62px 헤더, 본문 여백 24px/18px 구조를 사용한다. 작은 화면에서는 본문이 세로로 재배치되고 LNB는 서랍으로 동작한다.
  - 상단 액션은 `조회 · 월별 부과금액 · 빌라▾ · 호실▾ · 자동수납▾` 순서다.
  - `빌라`: 부과금액·미납내역·수납내역. 건물 미선택 시 먼저 건물을 선택하라는 안내를 표시한다.
  - `호실`: 명세서·영수증 출력. 건물과 호실 미선택 시 먼저 호실을 선택하라는 안내를 표시한다.
  - `자동수납`: 지로수납처리·지로수납원장·지로처리일자 확인·은행 입금내역 업로드·은행 양식 다운로드. 건물 선택이 필요하며, 각 메뉴는 대응하는 Figma 모달로 직접 진입한다.

### 3.1 건물·호실 선택 레일

- **기능**: 작업 대상 건물과 호실 선택.
- **규칙**:
  - 초기에는 `전체 건물`과 `코드 · 건물명 · 주소` 목록을 표시한다. 검색은 건물명·주소·코드를 부분 일치로 찾는다.
  - 건물 행을 선택하면 같은 영역이 `호수 · 세대주` 목록으로 전환된다. 검색은 호수·동·세대주를 부분 일치로 찾는다.
  - 뒤로가기는 건물과 호실 선택을 모두 해제하고 전체 건물 목록으로 돌아간다.
  - 호실 행 선택 시 해당 행을 강조하고 우측 수납·입주자·A/S 패널을 같은 세대로 갱신한다. 공실은 세대주를 `공실`로 표시한다.
  - 하단 `부과시 참조사항`은 건물 단위 데이터다. `payment` 권한자는 수정→저장할 수 있고, 미선택/미등록 상태에는 안내 문구를 표시한다.

### 3.2 수납 이력

- **기능**: 선택 호실의 최근 월별 부과·수납 내역 조회 및 편집.
- **규칙**:
  - 컬럼은 `년월 · 당월계 · 연체 · 수납액 · 수료 · 수납일자 · 은행 · 구분 · 비고 · 기한`이다. Figma의 `수료`는 데이터 필드 `fee(수수료)`에 매핑한다.
  - 최근 5개 부과월을 최신순으로 표시하고, 같은 월에 여러 수납 건이 있으면 수납 건별 행을 만든다.
  - 하단 합계는 `미납 · 연체료 · 미납합계`를 표시한다.
  - 호실 미선택 시 카드 아이콘과 `호수를 선택해 주세요` 안내를 표시한다.
  - `추가`는 빈 수납 폼, 행 선택 후 `수정`은 선택 수납의 수정 폼을 연다. 수정은 기존 건 취소+재기록 단일 트랜잭션으로 처리한다.
  - 편집 폼에서 수납액·수수료·은행·구분·수납일자·비고를 입력하며, 기존 수납 취소도 가능하다.
  - **구분** = 수납 구분(일반·지로·이체·무통), **은행** = 입금 은행(무통장입금·지로입금, 선택 안 함 가능) — [_status-codes.md](../../_status-codes.md) 3절. 처리 유형(완납·원금·분할)은 처리 버튼(수납·원금·수.연)이 정하고 열로 표시하지 않는다(2026-10-10).
  - `수.연`은 그 달 연체료를 나눈 시점 금액으로 `연체료 이전` 행(연체료 미수금)에 옮겨 저장한다. 원 행 연체료는 그만큼 줄고, 이전 행은 `수납`으로만 받으며(원금 없음) 받은 수납은 그 미수금에 연결돼 원금 수납으로 보지 않는다. 수납이 없는 이전 행은 `삭제`로 취소할 수 있다(2026-10-10, 0292).
  - 삭제(취소)한 수납은 음영으로 남고, 편집 중 `되살리기`로 예약해 저장하면 정상 수납으로 복구된다. 수정으로 대체된 취소 건은 이중 수납 방지를 위해 되살릴 수 없다(감사 로그 `PAYMENT_RESTORE`).
  - `추가` 행에서는 그 달 **당월계·연체**도 입력할 수 있고, 저장하면 실제 부과·연체로 반영된다(같은 트랜잭션, 감사 로그 `BILLING_OVERRIDE`). 당월계 = 그 달 고지 확정 금액(확정이 없던 달은 새로 확정, 항목 내역은 만들지 않음). 연체 = 그 달 수동 연체료(`billing_confirmations.late_fee_override`) — 미납 원금이 남은 달에만 적용되며 연체 현황·세입자 고지서에도 같은 값을 쓴다. 연체 칸을 비우고 저장하면 자동 계산으로 돌아가고, 손대지 않은 칸은 저장하지 않는다. 고지 확정이 없는 달은 당월계 없이 연체만 지정할 수 없다.
  - `문자 전송`은 선택 세대의 미납 안내 프리셋으로 공용 발송 모듈을 연다.

### 3.3 입주자 정보

- **기능**: 선택 호실의 현재 입주자 및 발송·부과 설정 조회/수정.
- **규칙**:
  - 컬럼은 `입주자명 · 입금자명 · 전화번호 · 입주일 · 퇴거일 · 적요 · 문자 · 알림톡 · 부과 · 출력`이다.
  - 호실 미선택 시 `호실을 선택하면 입주자정보가 표시돼요`, 입주자 미등록 시 `등록된 입주자 정보가 없습니다 (공실)`을 표시한다.
  - `수정`에서 기본정보와 문자·알림톡 수신동의, 부과/출력 여부를 편집하고 저장 또는 취소한다.

### 3.4 A/S 현황·접수

- **기능**: 선택 건물/호실의 A/S 접수와 처리 내역 관리.
- **규칙**:
  - 범위는 `호실 / 건물 전체`, 처리결과 필터는 `전체 / 미결 / 완결 / 보류 / 반복`이다. 호실 미선택 시 호실 범위 버튼을 비활성화한다.
  - 컬럼은 `No · 접수일시 · 유형 · 접수내용 · 입주자 전화번호 · 처리결과 · 처리결과 내용 · 시행일자 · 시간 · 접수자 · 담당자`다.
  - 건물 미선택 시 헤더와 `건물과 호수를 선택해 주세요` 안내를 표시한다. 선택 범위의 접수가 없으면 빈 결과 안내를 표시한다.
  - `+ 접수 추가`는 건물 선택 후 사용할 수 있다. 건물·호수·접수자·담당자·접수일시·유형·전화번호·접수내용·처리결과·시행일자·시간·처리결과 내용을 단일 폼에서 입력한다.
  - 행 선택은 동일 필드의 상세 폼을 열고 삭제·확인문자 보내기·저장을 제공한다. 시행일자와 처리결과 내용은 최신 처리이력 1건을 갱신하며 과거 이력은 보존한다.
  - 확인문자는 입주자에게 `민원·AS 처리 안내` 프리셋으로 발송한다. 알림톡 동의 시 알림톡, 미동의 시 SMS로 자동 전환한다.

### 3.5 통합조회·출력

- **기능**: 현재 선택과 무관하게 세대/금액을 찾고 보고서를 출력.
- **규칙**:
  - `조회` 모달은 기간을 기준으로 금액, 입금자명, 전화번호, 동호를 각각 조회한다. 결과는 청구금액·이사정산·세입자·건물주 영역으로 나뉜다.
  - 결과 행을 선택하면 모달을 닫고 좌측 건물·호실 및 우측 패널을 해당 대상으로 이동한다.
  - `월별 부과금액`, 빌라 부과금액·미납내역·수납내역, 호실 명세서·영수증은 화면 미리보기와 브라우저 인쇄를 제공한다.

### 3.6 자동수납

- **기능**: 지로·은행 입금 파일을 수납 데이터로 반영.
- **규칙**:
  - `지로수납처리`를 누르면 지로 업로드 모달로 직접 진입하며, 은행 지로 파일을 업로드해 파싱·검증 후 반영한다.
  - `지로수납원장 보기`를 누르면 원장 모달로 직접 진입하며, 조회 기간과 에러 상태(전체/정상/이중수납)로 필터링하고 일자별 소계, 총건수·수납액·수수료·실입금액을 표시한다.
  - `지로처리일자 확인`을 누르면 달력 모달로 직접 진입하며, 달력과 일자별 지표로 처리 내역을 확인한다.
  - 은행 입금내역은 `xlsx · xls · csv` 파일 업로드→열 매핑→자동 매칭 미리보기→미매칭 세대 수동 지정→일괄 확정 순서다.
  - 은행 양식 다운로드는 업로드용 빈 엑셀 템플릿을 내려받는다.

### 3.7 진입 알림 모달 (화면 진입 시)

- **기능**: 수납관리 화면 진입 시, 담당자가 놓치기 쉬운 세대를 팝업으로 안내한다. 두 종류를 순차 표시한다.
- **규칙**:
  - **오늘 입주 예정 세대**: `입주예정일(move_in_date)`이 오늘인 입주중 세대 목록. 카드 = `건물명 호실 · 세대주` + `입주예정 YYYY.MM.DD`.
  - **임대 만료 예정 세대**: `임대 만료일(end_date)`이 오늘부터 N일 이내인 입주중 세대 목록(N = 셋업 설정 > 알림 설정의 `만료 N일 전`, 설정 행이 없으면 7일). 카드 = `건물명 호실 · 세대주` + `만료예정 YYYY.MM.DD · D-N` + `만료 임박` 배지. 만료일이 가까운 순 정렬.
  - **알림 설정 연동**: 셋업 설정 > 알림 설정에서 끈 알림은 표시하지 않는다(입주 예정·임대 만료 각각 on/off).
  - **표시 순서**: 입주 예정 → (닫은 뒤) 임대 만료 예정. 해당 목록이 비어 있으면 그 모달은 건너뛴다.
  - **닫기(X·닫기 버튼)**: 이번 진입에 한해 닫음(같은 화면 재진입·새로고침 시 다시 표시).
  - **오늘 그만보기**: 오늘 하루 해당 알림을 표시하지 않음(브라우저 localStorage, 조직·계정별 키. 자정이 지나면 다시 표시).
  - **알림 설정 ›**: 셋업 설정의 알림 설정 탭(`/staff/setup?tab=notifications`)으로 이동.
  - 대시보드(`/staff`)의 입주예정 알림과 별개로 동작한다(중복 노출 허용).
