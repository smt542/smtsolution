## 1. 목적

관리업체 직원이 **건물 유형별로 관리비 부과 항목**(관리비·승강기유지비·정화조 등)을 자유롭게 등록·관리하는 화면. 각 항목의 **반올림·일자계산·이월** 방식을 정해두면, 관리비 부과 세팅·계산이 이 규칙을 따른다.

## 2. 권한

| 사용자 | 접근 |
|---|---|
| staff (마스터) | O |
| staff (일반) | LNB "항목등록 관리" 권한 부여 시 O (계정별 설정형) |

- 권한 모델은 [_permission-matrix.md](../../_permission-matrix.md) 2절을 따른다. 마스터가 `staff-management`에서 계정별로 이 메뉴 접근을 부여/제한.
- **공과금 계산식 연결 필수항목(전기·수도료·가스)** 은 권한과 무관하게 모든 건물 유형에 각각 1개씩 활성 상태로 존재해야 한다. **필수 해제·명칭 변경·삭제 불가**(읽기 전용).

## 3. UI

### 3.0 상단 헤더
- **기능**: 화면 제목("항목등록 관리")과 안내.
- **규칙**: 좌측 공통 LNB, 우측 공통 RNB("A/S 접수·퇴실 신청 현황") 패널을 공유한다(공통 인프라). 본문은 건물 유형별 항목 관리 영역.

### 3.1 건물 유형 그룹
- **기능**: 관리 항목을 **건물 유형 단위로 묶어** 표시·관리.
- **규칙**:
  - 건물 유형(빌라·빌딩·아파트·오피스텔·상가 등, [_status-codes.md](../../_status-codes.md) 4절)별로 항목 그룹을 둔다.
  - 유형 **추가·이름 변경·삭제** 가능. 신규 유형 생성과 동시에 필수항목(전기·수도료·가스) 3개를 자동 등록한다. 기존 유형에 누락·소프트 삭제·필수 해제된 항목이 있으면 DB 백필과 화면 복구 로직으로 자동 보완한다. 유형 삭제 시 그 그룹의 항목도 함께 제거(확인 모달).
  - **삭제 제한**: 건물에 배정되어 있거나 부과 이력이 있는 유형은 삭제를 **차단**한다 — 과거 고지서·정산 데이터 보호. 미사용 유형만 확인 모달 후 삭제.

### 3.2 관리 항목 목록/입력
- **기능**: 각 건물 유형에 속한 부과 항목을 등록·수정·삭제.
- **규칙**:
  - 항목 필드: **항목 명칭 · 반올림 · 일자계산 · 이월** ([_data-dictionary.md](../../_data-dictionary.md) E1).
  - 건물 유형당 **최대 20개**. 20개 도달 시 추가 차단.
  - **드래그로 순서 변경** 가능(부과·출력 순서에 반영). 
  - 삭제는 확인 후 실행, **삭제 실행취소** 지원. 항목 삭제는 소프트 삭제로 처리해 기존 부과 이력과 참조 데이터는 보존한다(3.1 규칙).
  - **필수항목(전기·수도료·가스)**: 모든 유형에 각각 1개씩 필수 등록. `is_required=true`·활성 상태를 강제하며 명칭 변경·필수 해제·삭제 불가, 순서 고정(읽기 전용). 직접 DB 변경으로 삭제·명칭 변경되더라도 정본 명칭으로 자동 복구한다.
  - 신규 항목 추가 시 **기본값(일반형)**: 반올림=`4사5입` · 일자계산=`적용` · 이월=`안함`.

### 3.3 반올림 설정 (항목별)
- **기능**: 항목 금액의 끝자리 처리 방식.
- **규칙**: `절상`(무조건 10원 올림) · `4사5입`(**10원 단위 반올림** — 1의 자리 1~4 버림, 5~9 올림. 예: 12,342→12,340, 12,345→12,350) · `절하`(무조건 10원 내림) · `그대로`(미적용). 계산 규칙은 [_calculation-rules.md](../../_calculation-rules.md) 1.2.

### 3.4 일자계산 설정 (항목별)
- **기능**: 실거주 일수 안분 여부.
- **규칙**: `적용`(실거주 일수로 일할, 중간 입·퇴실 반영, 분모 **고정 30일**) · `안함`(정액). 계산식은 [_calculation-rules.md](../../_calculation-rules.md) 1.1.

### 3.5 이월 설정 (항목별)
- **기능**: 전월 부과금액을 다음 달로 유지할지.
- **규칙**: `이월`(전월 부과금액 다음 달 유지) · `안함`(매월 새 산정). 예: 수리비는 보통 `안함`. [_calculation-rules.md](../../_calculation-rules.md) 1.3.

### 3.6 저장
- **기능**: 변경 내용 저장.
- **규칙**:
  - 유형·항목 변경은 화면 초안에 먼저 반영하고, 변경이 있을 때 노출되는 **명시적 「변경 내용 저장」 버튼**으로 서버에 일괄 반영한다(실수 방지). 성공·실패 결과는 토스트로 알리며, 저장 도중 일부 요청이 실패하면 서버 정본을 다시 조회해 화면을 동기화한다([_service-policy.md](../../_service-policy.md) 6절 성공 상태).
  - 조회 데이터에서 필수 3종이 누락됐거나 필수 플래그가 해제된 경우 화면이 즉시 잠금 항목으로 보완하고 저장 대상으로 표시한다. DB 마이그레이션은 기존 데이터 전체를 별도로 백필한다.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 로딩 | 유형·항목 조회 중 | 중앙 로딩 표시 |
| 빈 상태 | 건물 유형·항목 없음 | "등록된 건물 유형이 없습니다" + 상단 유형 추가 유도 |
| 성공 | 항목 있음 | 유형별 탭·항목 목록 |
| 편집 | 유형·항목 변경 발생 | 초안 유지 + 「변경 내용 저장」 노출 |
| 필수항목 복구 | 기존 유형에 전기·수도료·가스 누락 또는 필수 해제 | 화면에서 잠금 항목으로 즉시 보완 + 저장 대상 표시; DB는 백필·자동 복구 |
| 제한 | 유형당 20개 도달 | 추가 차단 + 안내 토스트 |
| 삭제 제한 | 건물 배정 또는 부과 이력 있음 | 유형 삭제 차단 + 안내 토스트 |
| 에러 | 조회·저장 실패 | 실패 안내·재시도([_service-policy.md](../../_service-policy.md) 6절) |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 관리 항목(명칭·반올림·일자계산·이월) | Supabase `fee_items` | 활성 항목 조회·생성·수정·소프트 삭제·순서 RPC |
| 필수 공과금 항목 정합성 | `fee_items` 제약·트리거·백필 마이그레이션 | 유형별 전기·수도료·가스 1개씩 활성·필수 상태 보장; 신규 유형 자동 생성; 직접 삭제·명칭 변경 시 복구 |
| 건물 유형 | Supabase `building_types` | 유형 조회·생성·이름변경·삭제·순서 RPC |
| 유형 삭제 사용 여부 | `buildings.type_id` · `fee_item_charges.fee_item_id` | 삭제 모달 진입 전 및 저장 시 재검증 |

- 발송 트리거 **없음**. 설정값은 관리비 부과 세팅(`management-fee-setting`)·부과 계산에서 참조.
