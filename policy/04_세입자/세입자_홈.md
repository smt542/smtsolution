## 1. 목적

세입자가 본인 세대의 **당월 관리비 요약·납부기한·최근 추이**와 **최신 건물 공지**를 한눈에 보는 홈. 앱은 **조회 전용**이며, 납부는 앱 내 결제가 아니라 **계좌 복사 후 은행 이체**로 한다.

---

## 2. 권한

| 사용자 | 접근 |
|---|---|
| resident (매칭 세대) | **R (조회 전용)** — 본인 세대 관리비·공지 열람 |

- 관리비·공지 등 모든 데이터는 **관리주체(staff)가 등록한 자료**를 표시만 한다(세입자 수정·납부 처리 없음).

## 3. UI

### 3.0 세대 헤더 + 알림
- **기능**: 현재 세대·사용자 표시 + 공지 알림 진입.
- **규칙**:
  - **건물·호수**(예: 그린빌라 201호) · **입주자명**(예: 박정호 님) · **관리주체명**(예: 스마일종합관리).
  - 우측 **알림(종) 버튼** — 미읽음 시 점(dot) 표시. 탭 → 공지 목록(`resident-notice`).

### 3.1 건물 공지 배너 (상시 안내문)
- **기능**: 건물 상시 공지문 노출 + 전문 열람.
- **규칙**:
  - staff `building-detail`에 입력된 **건물 상시 공지문**(건물 부가정보)을 요약(1줄) 상시 노출. 이 배너는 `resident-notice`(발행 공지 목록)와 **별개**다.
  - 탭 → **바텀시트**로 공지 **전문 열람**(제목 "건물 공지" + 본문 + 「확인」, 퇴실 신청·공지 목록과 같은 시트). 배경·Esc·「확인」으로 닫는다. 항상 열람 가능(2026-10-10).
  - 해당 건물에 입력된 공지문이 없으면 배너는 기본/비노출(운영 정책에 따름).

### 3.2 관리비 요약 카드
- **기능**: 당월 관리비 상태·금액 요약.
- **규칙**:
  - 기준 = **당월(가장 최근 부과월) 관리비**(예: "2026년 7월 관리비").
  - **상태 뱃지**: `미납` / `납부완료`([_status-codes.md](../../_status-codes.md) 수납 상태).
  - **대표 금액**: **미납 시 = 당월 부과액 + 연체료 합계**(예: 121,600 + 6,800 = 128,400원). 완납이면 부과액(연체료 0).
  - 함께 표시: **납부기한** · **당월 부과액** · **연체료**(별도).
  - **「상세 내역 보기」** → 해당 월 고지서 상세(`resident-bill-detail`).
  - 음수/강조 색은 `CLAUDE.md`.

### 3.3 3개월 추이 인사이트
- **기능**: 최근 관리비 추이·비교.
- **규칙**:
  - 최근 **3개월 부과액(연체료 제외)** 막대 그래프(예: 5월 112,400 · 6월 118,200 · 7월 121,600).
  - **3개월 평균 vs 이번 달** 비교 문구("최근 3개월 평균보다 N원 많아요/적어요"). 평균·이번 달 값 표시.

### 3.4 퇴실 신청
- **기능**: 세입자가 희망 퇴실일로 퇴실을 신청하고, 진행 상태를 확인·변경·취소.
- **규칙**:
  - **진행 상태 카드**(신청이 있을 때만 노출): "퇴실 신청 확인 중" + **희망 퇴실일 · D-day**. 탭 → 신청 현황 시트.
  - **신청 시트(폼)**: **희망 퇴실일**을 **달력**으로 선택. **최종 검침을 위해 최소 3일 이상 여유**를 둬야 선택 가능(과거·근접일 비활성). 날짜 선택 전 「퇴실 신청하기」 **비활성**.
  - **진행 순서 안내(3단계)**: ① 담당자가 확인 후 **1영업일 안에 전화 연락** ② 확정 퇴실일에 **최종 검침·관리비 확정** ③ **미납·연체료 차감 정산 결과 안내**.
  - **신청 제출** → 상태 `received`(담당자 확인 대기). staff의 **퇴실 신청 현황**으로 연동(처리 주체는 staff).
  - **현황 시트(신청 후)**: "담당자가 확인 중" + 희망 퇴실일·신청일. **희망일 변경**(달력 재선택) · **신청 취소**(확인 모달 후 철회) 가능.
  - 신청이 없을 때 **시작 진입점은 `resident-me`(내 정보)의 "퇴실 신청"**이다(홈의 상태 카드는 신청이 존재할 때만 노출).

### 3.5 하단 탭 네비게이션
- **기능**: 앱 주요 탭 이동.
- **규칙**: **홈**(현재) · **관리비**(`resident-bill`) · **내 정보**(`resident-me`).
- `❓` "납부 이력" 등 일부 메뉴는 프로토타입에서 "준비 중" — 실제 제공 여부 미정.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 성공 | 당월 관리비 있음 | 요약 카드 + 추이 + 공지 |
| 미납 / 완납 | 수납 상태별 | 뱃지·금액 규칙(3.2) |
| 빈 상태 | 부과 내역 없음(신규·미부과월) | 관리비 없음 안내 |
| 로딩/에러 | 조회 중·실패 | 공통 표준 준용([_service-policy.md](../../_service-policy.md) 6절) |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 세대(건물·호수·이름·관리주체) | 세대·입주자 데이터([_data-dictionary.md](../../_data-dictionary.md) C) | 진입 시 |
| 당월 관리비(부과액·연체료·기한·상태) | 관리비·수납 데이터([_data-dictionary.md](../../_data-dictionary.md) E·F) | 진입 시 |
| 최근 3개월 부과액 | 관리비 이력 | 추이 계산 |
| 건물 상시 공지문 | staff `building-detail` 입력(건물 부가정보) | 배너·바텀시트 |
| 발행 공지(알림) | 공지 데이터(staff `notice-management`) | 알림 종 → `resident-notice` |
| 퇴실 신청 | 퇴실 신청 데이터(→ staff 퇴실 신청 현황) | 신청/변경/취소 시 |

- 앱 내 결제·납부 처리 **없음**(계좌 복사·이체는 `resident-bill-detail`). 발송 트리거 없음(퇴실 신청은 staff가 확인·연락).
