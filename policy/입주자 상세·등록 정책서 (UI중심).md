## 1. 목적

세대(호실)별 입주자의 **기본 정보·연락처·관리비 부과·공과금 고객번호·고지서·임대차·부동산(매물) 정보**를 등록하거나 수정하는 화면. 신규 등록과 기존 수정을 하나의 화면에서 모드 분기로 처리하고, **8개 섹션을 상단 단일 `등록 저장` 버튼으로 통합 저장**한다.

---

## 2. 권한

| 사용자 | 조건 | 접근 | 등록 | 수정 |
|---|---|---|---|---|
| 조직 소유자·플랫폼 관리자 | `role=org_owner` 또는 `platform_admin` | O | O | O |
| 그 외 인증 사용자 | `permissions`에 `tenants` 보유 | O | O | O |
| 입주자 관리 권한 미보유자 | `tenants` 미보유 | X | X | X |

- 역할명만으로 직원·현장직원을 일괄 허용하거나 차단하지 않는다. 화면 접근은 `hasModule(me, 'tenants')`로 판정하고, 저장 RPC도 내부에서 `current_user_has_module('tenants')`를 다시 확인한다(fail-closed).

## 3. UI

> 섹션은 **번호가 매겨진 카드**로 위→아래 나열된다. 각 카드 헤더에 순번 배지(①②…)와 섹션명, 우측 접기(collapse) 아이콘이 있다. 입력 그리드는 데스크톱에서 기본 **2열**, 모바일에서 **1열**로 전환하며, 메모/주소/테이블 등 전체 폭 필드는 모바일에서도 1열을 유지한다.

### 3.0 상단 헤더 영역

- **기능**: 현재 모드 표시 + 통합 저장 + 뒤로가기
- **규칙**:
  - 등록 모드: 헤더 타이틀 "호수·입주민 등록" (상단 브레드크럼 "건물·입주자 관리")
  - 수정 모드: 헤더 타이틀 "[호실명] · [입주자명]"
  - `등록 저장` 버튼: 8개 섹션 전체 통합 저장
  - `뒤로가기` 버튼: 변경 사항 있을 경우 "저장하지 않고 나가시겠습니까?" 확인 → 확인 시 입주자 목록으로 이동

### 3.1 섹션 ① 기본 정보

- **기능**: 입주자의 핵심 식별 정보 등록
- **규칙** — 입력 항목:
  - 호실 (텍스트, **필수**) — 예: 101
  - 입주자명 (텍스트, **필수**)
  - 입금자명 (텍스트, **필수** — 이름과 다를 수 있음)
  - 룸 (사전 등록된 룸타입 목록 드롭다운 선택, **필수**)
  - 인원 (숫자)
  - 평형 (텍스트/숫자, 선택) — 예: 18평 (`units.area_pyeong`)
  - 입주일 (달력, **필수**)
  - 입주예정일 (달력, 선택) — 미래 입주 예정 세대. 값 저장은 구현됐으나 도래 시 대시보드 팝업 알림은 미구현(→ `dashboard.md`) ❓
  - 할인 유형 (드롭다운, 기본 "일반") — 일반이면 할인 금액은 입력하지 않음
  - 할인 금액 (금액, 선택) — 할인 유형이 "일반"이 아닐 때만 입력
  - 기타적요 (자유 텍스트, 멀티라인)
  - 이사정산시적요 (자유 텍스트, 멀티라인 — 이사정산 화면과 연동)
  - 호실·입주자명·입금자명·룸·입주일 미입력 시 저장 불가
  - 층(`floor`)·용도(`usage_type`)는 이 화면에서 노출하지 않으며, 수정 시 기존 값 보존·신규 등록 시 각각 `null`/`residential` 기본값(공과금 혼합건물 부과와 정합)

### 3.2 섹션 ② 연락처·차량

- **기능**: 연락처·차량번호(복수) 및 수신 동의 설정
- **규칙** — 입력 항목:
  - 전화번호 (텍스트, **첫 번째 필수**) — `＋ 전화번호 추가`로 복수 입력. 1~3번째는 주/부/집전화로 매핑, 4번째부터는 추가 목록에 누적
  - 차량번호 (텍스트, 선택) — `＋ 차량번호 추가`로 복수 입력
  - 문자 수신 (동의 / 거부 선택)
  - 알림톡 수신 (동의 / 거부 선택)
  - 홈피 비번 (텍스트, 선택) — 입주자 홈페이지 로그인용 비밀번호
  - 신규 등록 기본값: 문자 수신·알림톡 수신 모두 `동의`

### 3.3 섹션 ③ 관리비·부과

- **기능**: 세대별 관리비 금액·부과 정책 설정
- **규칙** — 입력 항목:
  - 관리비 (금액) — 세대 정액 관리비
  - 이사청소 (금액) — 이사청소비
  - 인상액 (금액)
  - 부과금 여부 (Y / N)
  - 부과일 (텍스트) — 예: 매월 1일
  - 이체 방식 (드롭다운: 지로 / 계좌이체 / 자동이체 / 무통장입금 / 없음)
  - 연체료 부과 여부 (Y / N)
  - 단수 출력 여부 (Y / N)
  - 부과시 참조사항 (자유 텍스트, 멀티라인) — 관리비 부과 시 참조
  - 신규 등록 기본값: 부과금 `Y`, 이체 방식 `지로`, 연체료 `N`, 단수 출력 `N`

### 3.4 섹션 ④ 공과금 고객번호

- **기능**: 세대별 공과금 고객번호(등록 목록에서 선택)·계량기 번호 등록
- **규칙** — 입력 항목(각 공과별 고객번호 + 계량기 번호):
  - 수도 고객번호 (드롭다운 — 건물 등록 고객번호 `kind=water`) + 수도 계량기 번호 (텍스트)
  - 전기 고객번호 (드롭다운 — `kind=elec`) + 전기 계량기 번호 (텍스트)
  - 공용 전기 고객번호 (드롭다운 — `kind=common_elec`) + 공용 전기 계량기 번호 (텍스트)
  - 가스 고객번호 (드롭다운 — `kind=gas`) + 가스 계량기 번호 (텍스트)
  - 한전고객번호 (텍스트) + 한전계기번호 (텍스트)
  - 고객번호 드롭다운 후보는 `공과금 관리 > 고객번호 조회`에 등록된 건물별 고객번호에서 로드

### 3.5 섹션 ⑤ 고지서

- **기능**: 고지서 출력·발송·이름 표기 설정
- **규칙** — 입력 항목:
  - 고지서 출력 여부 (Y / N)
  - 고지서 이름 출력 유형 (이름 미출력 / 이름 출력 / 코드 출력)
  - 발송 (우편 고지서 / 알림톡 고지서) — "알림톡 수신 동의 세대는 알림톡 고지서로 발송돼요" 안내
  - 인증 (텍스트) — 인증 정보
  - 신규 등록 기본값: 고지서 출력 `Y`, 이름 미출력, 알림톡 고지서

### 3.6 섹션 ⑥ 전출정보

- **기능**: 이전 전출자(퇴실) 이력 확인 (읽기 전용)
- **규칙**:
  - 퇴실 처리 시 해당 시점 입주자 정보가 자동 누적 저장
  - 이사일 내림차순 표시
  - 표시 항목(테이블): 이사일 / 이름 / 집전화 / 전화번호(주) / 전화번호(부) / 입주일
  - 수정 모드의 기본 정보 하단에 기존 퇴실 제어를 유지: 즉시 퇴실, 퇴실일 예약, 예약 취소
  - 즉시 퇴실 시 오늘 날짜로 전출 이력을 저장하고 세대를 바로 공실로 전환
  - 예약 퇴실은 지정일을 저장하며, 기존 목록/상세 진입 시 실행되는 만기 처리 흐름을 유지

### 3.7 섹션 ⑦ 임대 정보

- **기능**: 세대 임대차 계약 정보
- **규칙** — 입력 항목:
  - 임대구분 (드롭다운: 월세 / 전세 / 매매)
  - 개시일 (달력) · 만료일 (달력)
  - 보증금 (금액) · 보증금일 (달력)
  - 임대료 (금액) · 전세금 (금액)
  - 은행/계좌 (텍스트) — 예: 국민 123456-00-7890
  - 계약 만료 알림(`expiry_alert`)은 이 화면에서 노출하지 않으며 기존 값 보존
  - 신규 등록 기본값: 임대구분 `월세`

### 3.8 섹션 ⑧ 부동산 정보

- **기능**: 세대를 매물로 관리하기 위한 매물 정보 + 시설 목록
- **규칙**:
  - **매물 정보** 입력 항목:
    - 물건명 (텍스트)
    - 물건 주소 (주소 + 상세주소). 현재 주소 검색 버튼은 주소 입력란에 포커스만 이동하며 외부 주소 검색 제공자는 미연동 ❓
    - 물건구분 (드롭다운: 원룸 등) · 거래형태 (드롭다운: 직거래 등) · 구분 (드롭다운: 월세/전세/매매)
    - 면적(㎡) (숫자) · 보증금 (금액) · 전세금 (금액) · 월세 (금액)
    - 관리비 내용 (텍스트) — 예: 월 5만원 (수도 포함)
    - 입주가능일 (달력)
    - 위치 (텍스트, 전체 폭)
  - **시설정보**: `＋ 항목 추가`로 시설 항목을 복수 등록 (에어컨·냉장고 등)
  - 신규 등록 기본값: 물건구분 `원룸`, 거래형태 `직거래`, 구분 `월세`

## 6. 미정 (Open Questions / 결정 로그)

**미결정**
- ❓ 할인 유형 코드 값 집합(일반 외) — 현재 화면의 정적 후보는 임시이며 운영 코드 확정 필요. 기본값은 `일반`.
- ❓ 입주예정일 도래 알림 — 대시보드 노출 위치, 반복/중복 방지, 확인 처리 정책과 구현 필요.
- ❓ 주소 검색 — 사용할 주소 제공자와 검색 결과의 주소·상세주소 바인딩 정책 확정 필요.
- ❓ 물건구분·거래형태 코드 값 집합과 부동산(매물) 정보의 외부 노출(세입자앱/공개 매물 리스트) 여부 — 현재 정적 후보와 저장은 내부 관리 용도.
