## 1. 목적

현장관리자(partner)가 로그인 후 **담당 건물의 A/S 목록(전체)**을 조회·검색·필터·정렬하되 **본인 담당 건은 "내 담당" 뱃지로 구분**하고, 개별 건 상세(`mobile-as`) 또는 신규 접수(`mobile-as-new`)로 진입하는 모바일 메인 화면. 하단 탭의 **홈** 자리이며 partner 표면의 기본 진입점이다.

---

## 2. 권한

| 사용자 | 접근 |
|---|---|
| partner (현장관리자) | O — **담당 건물 A/S 전체 조회 + 본인 담당 '내 담당' 표시 + 신규 접수 진입**(쓰기) |
| staff / resident | — (별도 표면) |

- partner는 **고정 기능 세트**이며, A/S는 **담당 건물 전체**를 대상으로 조회하되 **본인 담당 건은 '내 담당'으로 표시**한다([_permission-matrix.md](../../_permission-matrix.md) 3절, [_service-policy.md](../../_service-policy.md) 2.3).
- 이 화면 자체는 목록 **조회**이나, A/S는 partner의 쓰기 가능 영역이므로 신규 접수 진입 버튼을 노출한다.
- **발송 없음**(문자·알림톡 트리거 없음, [_notification-policy.md](../../_notification-policy.md) 3절).

## 3. UI

### 3.0 상단 헤더
- **기능**: 화면 제목("A/S현황 조회") + `＋ 신규 접수` 버튼.
- **규칙**: 신규 접수 버튼 → `mobile-as-new`로 이동.

### 3.1 검색
- **기능**: 목록 내 텍스트 검색.
- **규칙**: 검색 대상 = **건물명·호실·접수내용·유형**(입력 즉시 필터). placeholder "건물명·호실 검색".

### 3.2 상태 필터 (칩)
- **기능**: A/S 상태별 필터.
- **규칙**: `전체 · 미결 · 보류 · 완결 · 반복` 중 단일 선택. 상태값은 [_status-codes.md](../../_status-codes.md) 1절(A/S 처리결과/상태). 기본값 `전체`.

### 3.3 정렬
- **기능**: 목록 정렬 순서 변경.
- **규칙**: 하단 시트로 `최신순`(기본) · `오래된순` 선택. 정렬 기준 = 접수일시.

### 3.4 A/S 목록 카드
- **기능**: A/S 1건 요약 표시 + 상세 진입.
- **규칙**:
  - 카드 표시: **유형 · 상태 뱃지 · 건물/호실 · 접수내용(2줄) · 접수일자 · 담당자(본인이면 '내 담당' 뱃지, 아니면 담당자명)**.
  - 유형·상태값은 [_status-codes.md](../../_status-codes.md) 1절. 상태 색상(미결=red·보류=amber·완결=green·반복=violet)도 동 문서 기준.
  - 카드 탭 → `mobile-as`(상세)로 이동.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 빈/결과없음 | 필터·검색 결과 0건 | "해당하는 접수 내역이 없어요" 안내 |
| 성공 | 목록 있음 | 카드 목록 표시 |
| 로딩 | 진입 시 목록 조회 중 | 공통 표준 준용([_service-policy.md](../../_service-policy.md) 6절) |
| 에러 | 조회 실패 | 실패 안내·재시도(공통 표준) |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
