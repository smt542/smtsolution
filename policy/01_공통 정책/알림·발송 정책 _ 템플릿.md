# 주택관리ERP — 알림·발송 정책 / 템플릿 (Notification Policy)

> 문자·알림톡·팩스 **발송 채널·과금·트리거·수신자·템플릿**의 공통 정의. 여러 화면이 발송을 트리거하고 포인트 과금과 직결되므로 공통으로 관리한다. (62개 화면 검토 기반)
> 상위 참조: [_service-policy.md](_service-policy.md) (과금·감사) · 코드값 [_status-codes.md](_status-codes.md) 11절

## 1. 발송 채널

| 채널 | 발신자(기본) | 단가(기본) | 용도 |
|------|-------------|:---:|------|
| **알림톡** (카카오) | 관리비서 채널 | 12원/건 | 공지, 관리비 발행, 세대 승인 알림 등 |
| **문자(SMS)** | 042-632-8770 | 20원/건 | A/S 확인, 독촉, 개별/단체 문자 |
| **팩스** | 발신 팩스번호 지정 | 50원/페이지 | 건물주·관계처 고지서 발송 |

> 단가는 admin `settings`에서 설정, `points`·`usage`에 반영. 카톡(카카오) 고지서도 알림톡 채널 계열.

## 2. 과금 (포인트) — 상세는 [_service-policy.md](_service-policy.md) 4.1

- 관리업체(테넌트)가 외부에서 **선불 충전** → `points`(1원=1P) 기록.
- **발송 1건마다 채널 단가만큼 포인트 차감**. `usage`가 발송 건수를 계측.
- 잔액 상태: 정상 → 충전 필요(≤기준) → **발송 중단(≤0, 하드 스톱)**.
- 본사(admin)는 월별 발송비를 집계해 `usage`에서 **청구서 발행**(공급가+부가세 10%).

## 3. 발송 트리거 (화면별)

발송 UI가 실제로 있는 화면은 **staff 5개 + partner 1개(모듈 호출)**. 나머지 화면은 발송 없음.

| 화면 | 채널 | 발송 종류 |
|------|------|-----------|
| staff `notice-management` | 알림톡 | 공지 전송/재전송 (**urgent 유형은 즉시 발송**), 수신자=대상 건물 세대 |
| staff `overdue-management` | 문자(SMS) | 독촉 문자 (대상: 연체 2개월↑ AND 10만원↑ 세대 자동 추출) |
| staff `receipt-management` | 문자(SMS) | A/S 확인 문자 — 템플릿 3종: **접수 확인 / 방문 예정 / 처리 완료** |
| staff `bill-publish` | 팩스 | 건물주·관계처 고지서 팩스 발송 |
| staff `messaging` | 문자·알림톡 | 예약/즉시 발송 허브 (관리비 고지·정기점검·건물주 정산·수도검침·청소일정 등) |
| partner `mobile-moving-settlement` | 문자 | "정산내역서 문자 전송" → staff `messaging` **공용 모듈 호출**(자체 발송 아님) |

> staff 검침·수납·이사정산·건물·입주자 화면 등은 발송 버튼이 없다. 실제 발송은 `messaging` 허브로 일원화하는 것이 원칙.

## 4. 수신자

| 대상 | 설명 |
|------|------|
| 입주자 | 세대 **주번호·부번호 모두** 수신(정책서 A-11) |
| 건물주 | 정산·고지 등 |
| 청소 담당자 | 청소팀 단체 문자 |
| 범위 | 전체 / 특정 건물 단위 선택 + 인원수 표시 |

## 5. 템플릿 (messaging)

- 구성: `구분, 템플릿명, 템플릿 내용, 링크(버튼명·링크토큰), 변수`
- **변수 치환** 지원(건물명·호수·금액·납기일 등).
- 예약 유형: 예약 / 예약(매월) / 예약(매주). (예: 20일 일괄 고지서 발송, 그룹 구분)
- 대표 템플릿 예: 관리비 고지, 정기 점검 안내, 건물주 정산 안내, 수도 검침 안내, 청소 일정 안내, A/S 접수확인·방문예정·처리완료, 미납 독촉.

## 6. resident(세입자) 수신 & 딥링크

- 세입자는 **하나의 통합 알림톡 토글**로 수신 관리: `관리비 발행`·`건물 공지`를 한 토글로 동시 on/off (resident-notify 최초 동의, resident-me 통합 토글 재설정).
- **guest 딥링크**: 알림톡의 버튼을 통해 로그인 없이 열람.
  - 관리비 확인: `resident-bill-detail?mode=guest` (발송일 기준 유효기간 만료)
  - 공지 확인("공지확인하기"): `resident-notice-detail` (기간 만료)
- 세대 승인/확인 결과도 알림으로 통지(resident-verify/pending).

## 7. 공통 규칙

- 발송 실패 시 사용자에게 실패 사유·재시도 안내, 원본 데이터 훼손 금지([_service-policy.md](_service-policy.md) 6절 에러 표준).
- 포인트 잔액 0이면 발송 차단(하드 스톱) — 발송 화면에서 잔액 상태 안내.
- 발송 이력은 `messaging` 발송 내역(채널·수신자·상태·발송일시)에 기록.
- 개인정보(연락처) 취급은 개인정보 정책 준수([_service-policy.md](_service-policy.md) 8절).
