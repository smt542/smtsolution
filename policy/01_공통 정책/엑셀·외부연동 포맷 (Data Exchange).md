# 주택관리ERP — 엑셀 / 외부연동 포맷 정의 (Data Exchange)

> 엑셀 업로드/다운로드·은행·자동이체·데이터 이관 등 **외부 데이터 교환 포맷**을 정의한다. 여러 화면이 같은 포맷을 공유하므로 공통으로 관리한다.
> 상위 참조: [_service-policy.md](_service-policy.md) · 필드 [_data-dictionary.md](_data-dictionary.md)
> ⚠️ 아래 컬럼은 **데이터 사전 기준 제안(표준안)**. 기존 실제 양식(xlsx)이 확인되면 그 컬럼을 정본으로 맞춘다.

## 0. 공통 규칙

- 인코딩 UTF-8, 1행 헤더, 시트 1개 기준(별도 명시 없으면).
- 업로드 시 **키 매칭 → 미매칭 건은 수동 처리**(사용자에게 목록 제시).
- 다운로드는 조회 결과 그대로(필터 반영).

---

## 1. 건물·입주자 일괄 등록 (building-list, 기존 전산 이전)

### 1.1 건물 일괄등록 (제안)
`건물코드, 건물명, 건물유형, 주소, 공동현관, 건물주명, 건물주전화(주), 건물주전화(부), 사무담당자, 현장관리자, 청소담당자, 계약일`

### 1.2 입주자 일괄등록 (제안)
`건물코드, 호실, 입주자명, 입금자명, 룸타입, 인원, 평형, 전화번호(주), 전화번호(부), 차량번호, 입주일, 관리비, 이체방식, 수도고객번호, 전기고객번호, 가스고객번호, 문자수신(동의/거부), 알림톡수신(동의/거부)`
> 필드 정의: [_data-dictionary.md](_data-dictionary.md) C절.

## 2. 은행 입금내역 자동수납 (receipt-management, payment-processing)

- **업로드(은행 → 시스템)**: 은행 입금내역 엑셀. 매칭 키 = **고객번호 · 이름 · 금액**. 미매칭 건은 수동 수납.
  - 제안 컬럼: `입금일, 입금자명, 입금액, 고객번호(있으면), 적요`
- **매칭 결과**: 매칭 성공 → 자동 수납 처리(구분: 이체/무통), 실패 → 수동 처리 목록.

## 3. 효성CMS 자동이체 (payment-processing)

절차(기능정의서 F-4): 회원번호 등록 → 엑셀 다운 → **회원번호 오름차순 정렬** → 청구금액 붙여넣기 → 대량청구 생성.
- 세대 필드: 효성 회원번호(숫자 8자리) · 계약번호(숫자 3자리) — [_data-dictionary.md](_data-dictionary.md) C3.
- 제안 컬럼(다운/청구): `효성회원번호, 건물명, 호실, 입주자명, 청구금액`
- 자동이체 세대 목록 다운로드(필터) 지원.

## 4. 데이터 이관 (setup · admin tenant-detail)

기존 전산 → 신규 시스템 이전. 3그룹 순차(마스터 → 건물 하위 → 이력). 대상 8종(`data-kind`).

| 그룹 | 이관 대상(kind) | 제안 컬럼(데이터사전 근거) |
|------|-----------------|------|
| 1 마스터 | vendorMaster(거래처), building(건물 기본) | 거래처: 구분·업체명·연락처 / 건물: 건물코드·건물명·유형·주소·건물주·담당자 |
| 2 건물 하위 | vendor(협력업체), util(공과금 고객번호), feeitem(항목 단가), tenant(입주자) | 협력업체: 건물코드·구분·업체명·연락처·계좌 / 고객번호: 건물코드·유형(수도/공용전기/전기/가스)·고객번호·계량기번호·명의 / 항목단가: 건물유형·항목명·단가 / 입주자: [1.2]와 동일 |
| 3 이력 | meter(검침 시작지침), unpaid(미납 잔액) | 검침: 건물코드·호실·유형·시작지침·검침일 / 미납: 건물코드·호실·년월·미납액·연체료 |

- 이관 상태: 미실행 → 완료. 항목별 건수·완료일 기록. 양식 다운로드 → 작성 → 업로드.

## 5. 조회/현황 엑셀 다운로드

담당자별 필터·자동이체 세대·미납 현황·A/S 현황(건물별·월별) 등 조회 화면의 결과를 엑셀로 다운(필터 반영).

---

## 6. 화면 PRD로 넘긴 사항
- 각 엑셀의 **실제 컬럼 순서·헤더 명칭**(기존 양식 파일 확인 시 정본화).
- 은행별 입금내역 포맷 편차(은행마다 컬럼 상이) 매핑 규칙 — 해당 화면 PRD.
- 효성CMS 실제 파일 규격(회원번호 자리수·정렬 등 벤더 규격) — 연동 시점 확정.
